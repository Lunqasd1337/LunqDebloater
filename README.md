# LunqDebloater

PowerShell-скрипт для преднастройки ISO-образа Windows 11 перед установкой. Работает офлайн, через DISM, над `install.wim`:

- удаляет предустановленные Appx-приложения;
- удаляет компоненты Windows (Capabilities и Optional Features);
- по желанию встраивает обновления (`.msu`, `.cab`), чтобы Windows была свежей сразу после установки;
- по желанию встраивает драйверы (`.inf`), чтобы Windows сразу ставилась с драйверами под ваше железо;
- по желанию обновляет установщик и среду восстановления (WinRE) теми же обновлениями и драйверами;
- по желанию ставит программы через winget и выполняет ваши скрипты при первом входе в Windows;
- по желанию кладёт в ISO файл ответов: установка спрашивает меньше, а на старых компьютерах можно обойти требования TPM и Secure Boot;
- вносит изменения в реестр образа (кусты `SOFTWARE`, `SYSTEM` и профиль `Default`, от которого создаются все новые пользователи).

На выходе получается загрузочный ISO (BIOS + UEFI) с одной выбранной редакцией. Отдельный режим «Что в образе» ничего не собирает, а выгружает список приложений и компонентов редакции, чтобы было проще составить свой профиль.

## Ответственность

LunqDebloater меняет установочный образ Windows так, как Microsoft официально не поддерживает: удаляет приложения и компоненты и правит реестр. **Всё, что вы делаете с его помощью, вы делаете на свой страх и риск.** Автор не отвечает за потерю данных, неработающую или нестабильную систему, проблемы с обновлениями, активацией, гарантией или поддержкой производителя.

- Будущие накопительные обновления Windows могут не установиться или вернуть удалённое, если рассчитаны на вырезанные компоненты.
- Перед установкой на рабочий компьютер проверьте собранный ISO в виртуальной машине и сохраните важные данные.

Программа распространяется «как есть», без каких-либо гарантий (см. [LICENSE](LICENSE)).

## Требования

- Windows 11 и Windows PowerShell 5.1 (встроен в Windows). Если запустить скрипт из PowerShell 7, он сам перезапустится в 5.1: в PowerShell 7 командлеты DISM для Appx падают с ошибкой «Класс не зарегистрирован».
- Лучше собирать на Windows 11 той же версии, что и ISO, или новее. Модуль DISM берётся из системы, и DISM старой системы, особенно Windows 10, может не справиться со свежими обновлениями нового образа. Скрипт предупредит, если система старше образа.
- [Windows ADK](https://learn.microsoft.com/windows-hardware/get-started/adk-install), компонент **Deployment Tools** (нужен только `oscdimg.exe`).
- Около 25 ГБ свободного места на NTFS-диске для рабочей папки (по умолчанию `C:\LunqWork`).
- Оригинальный ISO Windows 11.

Скрипт сам проверит права администратора, наличие ADK и свободное место ещё до начала сборки и подскажет, что исправить.

## Папка Config

Все настройки лежат в одной папке `Config` рядом со скриптом. Ничего не нужно искать по разным папкам: что положили в `Config`, то и попадёт в образ.

| Что | Для чего |
|---|---|
| `Profile.json` | Что удалить из Windows и какие настройки реестра внести (см. «Профиль») |
| `Apps.txt` | Программы, которые поставятся через winget при первом входе (см. «После установки») |
| `Scripts\` | Ваши скрипты `*.ps1`, которые выполнятся после установки |
| `Drivers\` | Драйверы `.inf`, можно в подпапках (см. «Драйверы») |
| `Updates\` | Обновления `.msu`/`.cab` (см. «Обновления») |

Подсказка по каждому пункту лежит в [Config/README.txt](Config/README.txt). Драйверы и обновления в git не попадают.

Перед сборкой скрипт показывает сводку «Что войдёт в образ»: что нашлось в `Config`, с номерами. Лишнее можно выключить по номеру, ничего не удаляя из папки. Там же включается очистка хранилища компонентов, добавление обновлений и драйверов в установщик со средой восстановления и файл ответов (см. «Файл ответов»). Если чего-то нет, в сводке написано, куда это положить.

Чтобы держать несколько наборов настроек, скопируйте папку (например, в `Config-Office`) и запускайте с `-ConfigPath .\Config-Office`.

## Быстрый старт

1. Скачайте репозиторий (Code → Download ZIP) и распакуйте его.
2. Дважды щёлкните `Start.cmd`. Скрипт попросит права администратора.
3. Дальше он всё спросит сам: выберите ISO в окне, затем категории твиков, проверьте сводку «Что войдёт в образ» и выберите редакцию (у каждой редакции есть короткое пояснение).
4. Проверьте план сборки и подтвердите. Сборка обычно занимает 15-40 минут, в окне видно «Шаг N из M» с пояснением, что происходит.
5. В конце скрипт покажет итог: что удалено, чего не нашлось в образе, где лежит готовый ISO.

## Запуск с параметрами

Полное описание каждого параметра: `Get-Help .\LunqDebloater.ps1 -Full`. Для повторных сборок и автоматизации всё можно задать параметрами, тогда скрипт ничего не спрашивает и берёт всё, что есть в `Config`:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
Get-ChildItem -Recurse | Unblock-File   # если архив скачан из интернета

.\LunqDebloater.ps1 -IsoPath D:\Win11_26H2.iso -Edition "Windows 11 Pro"
```

Если не указать `-Edition` или `-Index`, скрипт покажет список редакций и спросит номер. Без `-IsoPath` он работает в пошаговом режиме, как через `Start.cmd`. Итоговый ISO по умолчанию появится рядом с исходным (`Win11_26H2_Lunq.iso`), лог запуска будет в папке `Logs` рядом со скриптом (см. «Логи и версия»).

| Параметр | Назначение |
|---|---|
| `-IsoPath` | Исходный ISO. Без него включается пошаговый режим |
| `-OutputIso` | Путь к итоговому ISO |
| `-ConfigPath` | Папка с настройками вместо `Config` рядом со скриптом |
| `-ProfilePath` | Свой JSON-профиль вместо `Config\Profile.json` |
| `-SkipCategory` | Id категорий профиля, которые нужно пропустить, через запятую |
| `-Index` / `-Edition` | Редакция по номеру или имени |
| `-WorkDir` | Рабочая папка. Скрипт очищает её целиком, поэтому подойдёт только новая или пустая папка (или созданная им раньше), но не корень диска и не папка с ISO |
| `-OscdimgPath` | Путь к `oscdimg.exe`, если ADK стоит не в стандартной папке |
| `-UpdatesPath` | Папка с обновлениями `.msu`/`.cab` вместо `Config\Updates` |
| `-DriversPath` | Папка с драйверами (`.inf`, можно в подпапках) вместо `Config\Drivers` |
| `-DriversToSetup` | Добавить драйверы контроллеров дисков ещё и в установщик (`boot.wim`) и среду восстановления (WinRE), если они не видят диск |
| `-UpdatesToSetup` | Встроить обновления Windows ещё и в установщик и WinRE |
| `-SkipUpdates`, `-SkipDrivers` | Не встраивать обновления или драйверы из `Config` |
| `-SkipApps`, `-SkipScripts` | Не ставить программы из `Apps.txt` или не выполнять скрипты из `Scripts` при первом входе |
| `-Unattend` | Положить в ISO файл ответов: без вопросов о лицензии и конфиденциальности, язык, регион и часовой пояс как на этом компьютере |
| `-BypassRequirements` | Добавить в файл ответов обход требований TPM 2.0, Secure Boot и памяти (включает `-Unattend`) |
| `-LocalAccount` | Добавить в файл ответов вход без учётной записи Майкрософт (включает `-Unattend`) |
| `-ListContents` | Не собирать ISO, а сохранить список приложений и компонентов редакции в файл |
| `-SkipAppx`, `-SkipComponents`, `-SkipRegistry` | Пропустить шаг |
| `-Label` | Метка тома итогового ISO, по умолчанию `LUNQ_WIN11` |
| `-SkipVersionCheck` | Не останавливаться, если сборка ISO не совпадает с `Requirements` профиля |
| `-CleanupComponents` | Очистить хранилище компонентов (`/ResetBase`): образ меньше, но обновления из него нельзя удалить |
| `-KeepWorkDir` | Не удалять рабочую папку после сборки |
| `-Force` | Перезаписать существующий итоговый ISO |

## Как устроен процесс

1. ISO монтируется, его содержимое копируется в рабочую папку.
2. Выбранная редакция экспортируется в отдельный `install.wim` (ESD при этом конвертируется в WIM).
3. `install.wim` монтируется, в него встраиваются обновления и драйверы (если выбраны), при желании обновляется WinRE и добавляется скрипт первого входа. В корень ISO кладётся файл ответов, если он включён. Затем применяется профиль: Appx, компоненты, реестр.
4. Образ сохраняется и пересжимается. Если выбрано, обновляется и установщик (`boot.wim`). `oscdimg` собирает загрузочный ISO.

При ошибке образ отключается без сохранения, а кусты реестра выгружаются.

## Логи и версия

Каждый запуск пишет лог в папку `Logs` рядом со скриптом, с самого старта: в него попадают и ошибки при выборе ISO, профиля и проверке системы. В первых строках лога указаны версия LunqDebloater, версия Windows и PowerShell и параметры запуска. Рядом лежит подробный лог DISM (`*_dism.log`): если DISM выдал ошибку, настоящая причина обычно видна только в нём. Хранятся логи последних 10 запусков и логи DISM последних 3 (они намного больше), более старые удаляются сами. Путь к логу показывается в плане сборки, в итоге и при ошибке.

Если что-то пошло не так, пришлите оба файла последнего запуска: `LunqDebloater_<дата>.log` и `LunqDebloater_<дата>_dism.log`.

Версия LunqDebloater видна в заголовке окна, в начале лога и в итоге сборки. Она же записывается в собранный образ вместе с настройками сборки. На установленной системе их можно посмотреть так:

```powershell
reg query HKLM\SOFTWARE\LunqDebloater
```

Там указаны версия и дата сборки, исходный ISO и редакция, файл ответов, профиль, включённые и пропущенные категории, встроенные обновления, число драйверов, программы и скрипты после установки. Если после установки что-то работает не так, по этим данным видно, чем и с какими настройками собран образ.

## Обновления

1. Скачайте накопительное обновление для своей версии из [каталога Центра обновления Майкрософт](https://www.catalog.update.microsoft.com), например по запросу `Windows 11 Version 26H2 x64`. Если в каталоге для него несколько файлов, скачайте все.
2. Положите файлы в `Config\Updates`. Они появятся в сводке перед сборкой, а с параметрами встроятся сами (если не нужно, добавьте `-SkipUpdates`).

Кладите только обновления для самой системы: накопительное обновление и обновление .NET. Обновления Safe OS и Setup Dynamic Update каталог показывает в том же поиске, но они для среды восстановления и установщика, в саму систему не встанут и попадут в итог как ошибки.

Обновления ставятся сразу после монтирования образа, по возрастанию номера KB, до удаления приложений и компонентов. Накопительное обновление ставится долго (10-30 минут) и требует дополнительного места. После обновлений имеет смысл включить `-CleanupComponents` (в сводке это пункт под обновлениями): старые версии системных файлов удалятся, и образ станет меньше.

## Драйверы

1. Положите распакованные драйверы (файлы `.inf` вместе с `.sys`, `.cat` и остальными) в `Config\Drivers`. Подпапки можно любые. Проще всего выгрузить все драйверы с компьютера, на который будет ставиться система: `Export-WindowsDriver -Online -Destination .\Config\Drivers`. Другие способы описаны в [Config/README.txt](Config/README.txt).
2. Драйверы появятся в сводке перед сборкой, а с параметрами встроятся сами (если не нужно, добавьте `-SkipDrivers`).
3. Если установщик не видит диск (контроллеры Intel RST/VMD, RAID), добавьте драйверы и в него: в сводке это пункт под драйверами, с параметрами нужен ключ `-DriversToSetup`. Тогда драйверы попадут и в среду восстановления (WinRE), и она тоже увидит диск. Туда добавляются только драйверы контроллеров дисков (класс `SCSIAdapter` или `HDC` в `.inf`): установщик при загрузке целиком распаковывается в память, и все драйверы сразу сильно замедлили бы её.

Драйверы попадают в хранилище драйверов образа, и Windows сама ставит подходящие во время установки. Каждый `.inf` добавляется отдельно, поэтому неподходящий драйвер не срывает сборку, а попадает в итог как ошибка. Драйвер в виде `.exe` без `.inf` встроить нельзя, его сначала нужно распаковать.

Это хорошо сочетается с категорией `drivers` профиля (по умолчанию выключена): она запрещает Windows Update ставить свои драйверы, а нужные вы встраиваете сами.

## Установщик и среда восстановления

Кроме самой системы в ISO есть ещё два образа на базе Windows PE:

- **установщик** (`sources\boot.wim`, образ 2), с которого загружается флешка;
- **среда восстановления** (WinRE, `Windows\System32\Recovery\Winre.wim` внутри системы), которая открывается при сбое загрузки и через «Параметры → Восстановление».

По умолчанию они остаются такими, как в ISO. С `-UpdatesToSetup` в них встраиваются те же обновления Windows, что и в систему, а с `-DriversToSetup` драйверы контроллеров дисков. В сводке перед сборкой это пункты под обновлениями и драйверами. Обновления .NET и прочие пакеты, которые не ставятся в Windows PE, пропускаются. После обновлений оба образа очищаются от старых файлов и пересжимаются. Сборка с обновлениями займёт на 10-20 минут дольше.

## После установки

Можно сделать так, чтобы при первом входе в установленную Windows поставились нужные программы и выполнились ваши скрипты:

1. В `Config\Apps.txt` уже есть готовый список: 7-Zip, DirectX и все версии Visual C++ Redistributable, которые нужны играм и многим программам. Добавьте свои программы (Id из winget, по одному в строке) или закомментируйте ненужные через `#`. В конце файла есть ещё примеры.
2. Если нужно, положите в `Config\Scripts` свои скрипты `*.ps1`. Они выполнятся после программ, по порядку имён, с правами администратора. Остальные файлы из этой папки тоже копируются, и скрипты могут ими пользоваться.
3. Программы и скрипты появятся в сводке перед сборкой, а с параметрами добавятся сами (если не нужно, добавьте `-SkipApps` или `-SkipScripts`).

При первом входе откроется окно с ходом работы. Скрипт дождётся интернета и winget, тихо поставит программы, выполнит скрипты и закроет окно. Если интернета нет, программа не поставилась или окно закрыли на середине, недоделанное повторится при следующем входе (до 5 попыток). Скрипт с ошибкой повторно не запускается. Когда всё сделано, копии ваших скриптов и всё, что лежало рядом с ними, удаляются с диска: там могут быть пароли и ключи. Остаются только `Apps.txt` и лог `C:\Windows\Setup\Scripts\Lunq\FirstLogon.log`. Подробности в [Config/README.txt](Config/README.txt).

Скрипты можно сохранять в любом редакторе. Windows PowerShell 5.1 читает файл в UTF-8 без метки BOM как ANSI, и русский текст в кавычках ломает весь скрипт. Поэтому при сборке такие файлы пересохраняются в UTF-8 с BOM, это видно в выводе шага.

Скрипт считается неудачным, если он выбросил ошибку или завершился с кодом выхода не 0. Код выхода берётся и от последней внешней программы в скрипте: например, robocopy возвращает 1 и при успехе. Если так и задумано, допишите в конце скрипта `exit 0`.

Если записываете флешку через Rufus, не отмечайте в его окне ни одну настройку Windows, в том числе обход требований TPM, Secure Boot и памяти. Для них Rufus добавляет свой файл ответов, Windows берёт его вместо файла LunqDebloater, и программы со скриптами после установки сами не запустятся. Обход требований и локальную учётную запись лучше включить в файле ответов LunqDebloater (см. «Файл ответов»). Если без настроек Rufus или своего `autounattend.xml` всё же не обойтись, после установки запустите всё вручную из PowerShell от имени администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Windows\Setup\Scripts\Lunq\FirstLogon.ps1
```

## Файл ответов

Файл ответов (`autounattend.xml` в корне ISO) отвечает за человека на часть вопросов установки Windows. Windows Setup находит его на флешке сама. В пошаговом режиме он включён по умолчанию (пункты под «Файл ответов» в сводке), с параметрами включается ключом `-Unattend`.

| Пункт сводки | Ключ | Что делает |
|---|---|---|
| Не спрашивать про лицензию и конфиденциальность | `-Unattend` | Лицензия принимается сама, все параметры конфиденциальности (диагностика, реклама, местоположение) выключены, страница с ними не показывается |
| Язык, регион и часовой пояс как на этом компьютере | `-Unattend` | Язык установщика и Windows берётся из образа, а формат, раскладки клавиатуры и часовой пояс с компьютера, на котором собирается ISO |
| Обойти требования Windows 11 | `-BypassRequirements` | Установка не проверяет TPM 2.0, Secure Boot и объём памяти. Для компьютеров, на которые Windows 11 иначе не ставится |
| Локальная учётная запись | `-LocalAccount` | Windows не предлагает войти в учётную запись Майкрософт и сразу спрашивает имя и пароль локальной |

Диск для установки, ключ продукта (можно нажать «У меня нет ключа») и сеть по-прежнему выбираются вручную: файл ответов ничего не стирает сам. Пароли в нём не хранятся, имя и пароль учётной записи вводятся при установке. Если в образе есть программы или скрипты после установки, их команда тоже записывается в этот файл.

С Rufus не отмечайте настройки Windows в его окне: он добавит свой файл ответов вместо этого. Работу файла ответов на настоящей установке стоит проверить в виртуальной машине: сборка проверялась только на заглушках.

## Что в образе

Чтобы составить свой профиль, полезно знать точные имена приложений и компонентов в своей редакции. В пошаговом режиме выберите в начале «Посмотреть, что есть в образе», а с параметрами добавьте `-ListContents`:

```powershell
.\LunqDebloater.ps1 -IsoPath D:\Win11.iso -Edition "Windows 11 Pro" -ListContents
```

Скрипт ничего не собирает и не меняет. Он копирует редакцию в рабочую папку, открывает её только для чтения и сохраняет рядом с ISO файл `<имя ISO>_<номер редакции>_contents.txt`. В файле перечислены приложения Appx, установленные компоненты (Capabilities) и функции Windows (включённые и выключенные). Справа у каждого элемента указаны категории профиля, которые его уже удаляют. В конце файла собраны записи профиля, которых нет в образе. Для этого режима Windows ADK не нужен.

## Профиль

Всё, что удаляется и меняется, описано в `Config\Profile.json`. Правьте его под себя или положите рядом ещё профили (`*.json`): тогда скрипт спросит, какой взять. Профиль состоит из категорий: в каждой собрано всё, что относится к одной теме (приложения, компоненты, функции и реестр), и её можно целиком включить или выключить.

```jsonc
{
  "Name": "Default",
  "Description": "Что делает профиль",
  "Options": { "RemoveFeaturePayload": false },   // удалять ли файлы отключённых функций
  "Categories": [
    {
      "Id": "ai",                                 // короткое имя для -SkipCategory
      "Name": "Copilot и ИИ",
      "Enabled": true,                            // false: категория пропускается
      "Description": "Что делает категория",
      "Appx":         ["Microsoft.Copilot"],      // DisplayName, можно с *
      "Capabilities": [],                         // Get-WindowsCapability, можно с *
      "Features":     ["Recall"],                 // Get-WindowsOptionalFeature
      "Packages":     [],                         // CBS-пакеты, осторожно
      "Registry": [
        { "Hive": "SOFTWARE", "Path": "Policies\\Microsoft\\Windows\\WindowsCopilot", "Name": "TurnOffWindowsCopilot", "Type": "REG_DWORD", "Value": 1 },
        { "Hive": "DefaultUser", "Path": "Software\\Microsoft\\Windows\\CurrentVersion\\Run", "Name": "OneDriveSetup", "Action": "DeleteValue" },
        { "Hive": "SOFTWARE", "Path": "Microsoft\\WindowsUpdate\\Orchestrator\\UScheduler_Oobe\\OutlookUpdate", "Action": "DeleteKey" }
      ]
    }
  ]
}
```

Пустые списки в категории можно не писать.

### Требования к версии Windows

Профиль может указать, на какую сборку Windows он рассчитан:

```json
"Requirements": { "Build": 26300, "MinRevision": 9457, "Architecture": "amd64" }
```

- `Build`: номер сборки должен совпадать точно (26300 соответствует 26H2, 26200 соответствует 25H2, 26100 соответствует 24H2).
- `MinRevision`: минимальная ревизия, то есть число после точки в `26300.9457`. Всё, что новее, подходит, так что профиль не нужно править после каждого ежемесячного обновления.
- `Architecture`: `amd64` или `arm64`.

Скрипт сверяет это с выбранной редакцией сразу после чтения ISO, ещё до копирования файлов. Если сборка не подходит, он останавливается и подсказывает, где скачать свежий ISO. Если не хватает только ревизии, а в папке обновлений есть накопительное обновление Windows, скрипт лишь предупреждает: обновление поднимет ревизию. Чтобы собрать образ на другой сборке сознательно, запустите скрипт с `-SkipVersionCheck`. Если блока `Requirements` в профиле нет, проверка не выполняется. Профиль старого формата (с `Appx`, `Registry` и т.д. на верхнем уровне, без `Categories`) тоже работает: он считается одной категорией.

Категории в `Profile.json`:

| Id | Категория |
|---|---|
| `apps` | Встроенные приложения |
| `legacy` | Устаревшие компоненты |
| `telemetry` | Телеметрия и диагностика |
| `ai` | Copilot и ИИ |
| `ads` | Реклама и предложения |
| `search` | Поиск и Bing |
| `store` | Microsoft Store |
| `drivers` | Драйверы из Windows Update |
| `onedrive` | OneDrive |

Пропустить категории без правки профиля: `-SkipCategory drivers,store`. В пошаговом режиме скрипт показывает список категорий, и их можно включать и выключать по номерам.

Записи реестра:

- `Hive`: `SOFTWARE` (HKLM\SOFTWARE), `SYSTEM` (HKLM\SYSTEM, используйте `ControlSet001` вместо `CurrentControlSet`) или `DefaultUser` (HKCU для всех новых пользователей).
- `Name`: имя значения. Если не указать, запись относится к значению «по умолчанию» у ключа.
- `Action`: `Set` (по умолчанию), `DeleteValue` или `DeleteKey`.
- `Type`: `REG_DWORD`, `REG_QWORD` (число или строка `"0x..."`), `REG_SZ`, `REG_EXPAND_SZ`, `REG_MULTI_SZ` (массив строк), `REG_BINARY` (hex-строка, например `"de ad be ef"`).
- `Value`: значение. Строки записываются как есть, с кавычками и `\` в конце.

Ошибку в записи (неизвестный тип или действие, не число в `REG_DWORD`) скрипт покажет сразу при чтении профиля, ещё до сборки.
- `Description` необязателен и нужен для будущего GUI.

Узнать точные имена в своём образе проще всего режимом «Что в образе» (см. выше). Вручную это можно сделать так (после `Mount-WindowsImage`):

```powershell
Get-AppxProvisionedPackage -Path C:\LunqWork\mount | Select DisplayName
Get-WindowsCapability     -Path C:\LunqWork\mount | Where State -eq Installed | Select Name
Get-WindowsOptionalFeature -Path C:\LunqWork\mount | Where State -eq Enabled | Select FeatureName
```

Категория `drivers` отключает загрузку драйверов из Windows Update и по умолчанию выключена. Если в системе нет встроенного драйвера сетевой карты или Wi-Fi, после установки не будет интернета, и драйвер придётся ставить вручную. Включайте её (`"Enabled": true` в профиле или по номеру в пошаговом режиме), только если встраиваете нужные драйверы в образ сами (см. раздел «Драйверы»).

Профиль по умолчанию не трогает Microsoft Store, App Installer (winget), Терминал, Фотографии, Калькулятор, Блокнот, Paint и Безопасность Windows. Списки `Packages` пусты намеренно: удаление CBS-пакетов может сломать установку обновлений.

## Разработка

Код разложен так:

| Путь | Что там |
|---|---|
| `LunqDebloater.ps1` | Сам скрипт: параметры, пошаговый режим, план и список шагов сборки |
| `Modules\LunqDebloater\` | Модуль с функциями. Версия задаётся в манифесте `LunqDebloater.psd1` |
| `Modules\LunqDebloater\Private\` | Функции по темам: `Console`, `Profile`, `Iso`, `Checks`, `Image`, `Servicing`, `Removal`, `Registry`, `PostInstall`, `Unattend`, `Inventory`, `Report`, `System` |
| `Modules\FirstLogon\FirstLogon.ps1` | Скрипт первого входа, который кладётся в образ |
| `Tests\` | Тесты Pester и заглушка модуля DISM |

Тесты не трогают систему: вместо DISM, reg.exe, oscdimg и winget работают заглушки, а сборка идёт в папке теста. Запустить их (нужен Pester 5):

```powershell
Install-Module Pester -MinimumVersion 5.5.0 -Scope CurrentUser -Force -SkipPublisherCheck
Invoke-Pester -Path .\Tests
Invoke-ScriptAnalyzer -Path .\LunqDebloater.ps1 -Settings .\PSScriptAnalyzerSettings.psd1
Invoke-ScriptAnalyzer -Path .\Modules -Recurse -Settings .\PSScriptAnalyzerSettings.psd1
```

То же самое GitHub Actions выполняет для каждого PR. Что поменялось в каждой версии, записано в [CHANGELOG.md](CHANGELOG.md).
