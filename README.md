# LunqDebloater

PowerShell-скрипт для преднастройки ISO-образа Windows 11 перед установкой. Работает офлайн, через DISM, над `install.wim`:

- удаляет предустановленные Appx-приложения;
- удаляет компоненты Windows (Capabilities и Optional Features);
- по желанию встраивает обновления (`.msu`, `.cab`), чтобы Windows была свежей сразу после установки;
- по желанию встраивает драйверы (`.inf`), чтобы Windows сразу ставилась с драйверами под ваше железо;
- по желанию обновляет установщик и среду восстановления (WinRE) теми же обновлениями и драйверами, а также Safe OS и Setup Dynamic Update;
- по желанию ставит программы через winget и выполняет ваши скрипты при первом входе в Windows;
- по желанию кладёт в ISO файл ответов: установка спрашивает меньше, а на старых компьютерах можно обойти требования TPM и Secure Boot;
- вносит изменения в реестр образа (кусты `SOFTWARE`, `SYSTEM` и профиль `Default`, от которого создаются все новые пользователи);
- по желанию сам скачивает свежие обновления из каталога Microsoft и пересобирает ISO каждый месяц;
- записывает рядом с ISO рецепт, по которому сборку можно повторить одной командой, и отчёт «до и после»;
- применяет тот же профиль к уже установленной Windows без ISO и умеет вернуть всё убранное;
- переносит в новый образ драйверы, программы и сети Wi-Fi этого компьютера.

На выходе получается загрузочный ISO (BIOS + UEFI, для ARM64 только UEFI) с одной выбранной редакцией. Отдельный режим «Что в образе» ничего не собирает, а выгружает список приложений и компонентов редакции, чтобы было проще составить свой профиль.

## Ответственность

LunqDebloater меняет установочный образ Windows так, как Microsoft официально не поддерживает: удаляет приложения и компоненты и правит реестр. **Всё, что вы делаете с его помощью, вы делаете на свой страх и риск.** Автор не отвечает за потерю данных, неработающую или нестабильную систему, проблемы с обновлениями, активацией, гарантией или поддержкой производителя.

- Будущие накопительные обновления Windows могут не установиться или вернуть удалённое, если рассчитаны на вырезанные компоненты.
- Перед установкой на рабочий компьютер проверьте собранный ISO в виртуальной машине и сохраните важные данные.

Программа распространяется «как есть», без каких-либо гарантий (см. [LICENSE](LICENSE)).

## Требования

- Windows 11 и Windows PowerShell 5.1 (встроен в Windows). Если запустить скрипт из PowerShell 7, он сам перезапустится в 5.1: в PowerShell 7 командлеты DISM для Appx падают с ошибкой «Класс не зарегистрирован».
- Лучше собирать на Windows 11 той же версии, что и ISO, или новее. Модуль DISM берётся из системы, и DISM старой системы, особенно Windows 10, может не справиться со свежими обновлениями нового образа. Скрипт предупредит, если система старше образа.
- [Windows ADK](https://learn.microsoft.com/windows-hardware/get-started/adk-install), компонент **Deployment Tools** (нужен только `oscdimg.exe`).
- Около 25 ГБ свободного места на NTFS-диске для рабочей папки (по умолчанию `C:\LunqWork`), с обновлениями и драйверами больше: ещё три размера обновлений и два размера драйверов. Точную цифру покажет проверка перед сборкой.
- Оригинальный ISO Windows 11.

Скрипт сам проверит права администратора, наличие ADK и свободное место ещё до начала сборки и подскажет, что исправить.

## Папка Config

Все настройки лежат в одной папке `Config` рядом со скриптом. Ничего не нужно искать по разным папкам: что положили в `Config`, то и попадёт в образ.

| Что | Для чего |
|---|---|
| `Profile.json` | Что удалить из Windows и какие настройки реестра внести (см. «Профиль») |
| `Apps.txt` | Программы, которые поставятся через winget при первом входе (см. «После установки») |
| `Scripts\` | Ваши скрипты `*.ps1`, которые выполнятся после установки |
| `Drivers\` | Драйверы `.inf`, можно в подпапках (см. «Драйверы») |
| `Updates\` | Обновления `.msu`/`.cab`, в подпапках `SafeOS\` и `Setup\` обновления для WinRE и установщика (см. «Обновления») |

Подсказка по каждому пункту лежит в [Config/README.txt](Config/README.txt). Драйверы и обновления в git не попадают.

Перед сборкой скрипт показывает сводку «Что войдёт в образ»: что нашлось в `Config`, по разделам «Обновления», «Драйверы», «Первый вход», «Установка Windows» и «Дополнительно». В строке раздела видно, что в нём включено, а номер открывает раздел с его пунктами. Лишнее можно выключить по номеру, ничего не удаляя из папки. Там же включается очистка хранилища компонентов, добавление обновлений и драйверов в установщик со средой восстановления и файл ответов (см. «Файл ответов»). Драйверы и обновления класть в `Config` не обязательно: пункты со стрелкой в сводке открывают окно выбора папки (например, «Загрузки» или флешка с драйверами производителя), а пункт «Взять драйверы с этого компьютера» выгружает драйверы текущей Windows. После этого сводка показывается снова, остальной выбор в ней сохраняется.

Чтобы держать несколько наборов настроек, скопируйте папку (например, в `Config-Office`) и запускайте с `-ConfigPath .\Config-Office`.

## Быстрый старт

Проще всего одной командой. Откройте PowerShell и выполните:

```powershell
irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1 | iex
```

Команда скачает последний релиз в папку `LunqDebloater` вашего профиля (`C:\Users\<имя>\LunqDebloater`) и запустит скрипт в пошаговом режиме, дальше пункты 3-5. Подробнее в разделе «Запуск одной командой».

Или вручную:

1. Скачайте репозиторий (Code → Download ZIP) и распакуйте его.
2. Дважды щёлкните `Start.cmd`. Скрипт попросит права администратора.
3. Дальше он всё спросит сам: выберите, собрать ISO или посмотреть, что в образе, затем ISO в окне, затем категории твиков, проверьте сводку «Что войдёт в образ», задайте имя итогового ISO (Enter оставит предложенное) и выберите редакцию (у каждой редакции есть короткое пояснение).
4. Проверьте план сборки и подтвердите. Сборка обычно занимает 15-40 минут, в окне видно «Шаг N из M» с пояснением, что происходит.
5. В конце скрипт покажет итог: что удалено, чего не нашлось в образе, где лежит готовый ISO.

## Запуск одной командой

`irm ... | iex` скачивает и выполняет [Install.ps1](Install.ps1). Его можно прочитать до запуска. Загрузчик делает вот что:

- узнаёт на GitHub последний релиз (не текущий `main`) и раскладывает его в `C:\Users\<имя>\LunqDebloater`. Папка в профиле выбрана потому, что скрипт работает из неё с правами администратора, а файлы в корне диска C: могут менять и другие пользователи компьютера;
- до распаковки сверяет архив релиза с `SHA256SUMS`, который приложен к релизу. Если сумма не совпала, ничего не меняется. У релизов до 1.12.0 такого файла нет, и для них загрузчик предупреждает, что архив не проверен;
- запускает `LunqDebloater.ps1` в Windows PowerShell 5.1, даже если команду ввели в PowerShell 7. Права администратора скрипт попросит сам.

Та же команда обновляет программу. Если версия уже последняя, скрипт сразу запускается. При обновлении папки программы заменяются целиком. Файлы в `Config`, которые вы изменили, остаются, и загрузчик их перечислит. Ваши файлы рядом (ISO, `Logs`) не трогаются. Без интернета запускается уже скачанная версия.

Другая папка задаётся так:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1))) -Path D:\LunqDebloater
```

В непустую папку, где нет LunqDebloater, загрузчик ничего не кладёт. Менять файлы в папке программы могут только вы, администраторы и SYSTEM: загрузчик сам ставит такие права, поэтому папка в корне диска тоже безопасна. Папку, которую создал другой пользователь компьютера, или папку с его файлами загрузчик не берёт: владелец файла всегда может вернуть себе права на него. На флешке с FAT32 или exFAT прав доступа нет, и загрузчик об этом предупредит.

### Ярлык на рабочем столе

Ярлык с этой командой при каждом запуске проверяет обновления и запускает последнюю версию. Щёлкните правой кнопкой по рабочему столу, выберите «Создать» → «Ярлык» и вставьте в поле «Укажите расположение объекта»:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1 | iex"
```

Назовите ярлык, например, «LunqDebloater». Окно не закроется само: в конце скрипт ждёт Enter.

## Запуск с параметрами

Все параметры описаны в таблице ниже. `Get-Help .\LunqDebloater.ps1` показывает их список и ссылки на это описание, а `Get-Help .\LunqDebloater.ps1 -Online` открывает его на GitHub. Для повторных сборок и автоматизации всё можно задать параметрами, тогда скрипт ничего не спрашивает и берёт всё, что есть в `Config`:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
Get-ChildItem -Recurse | Unblock-File   # если архив скачан из интернета

.\LunqDebloater.ps1 -IsoPath D:\Win11_26H2.iso -Edition "Windows 11 Pro"
```

Если не указать `-Edition` или `-Index`, скрипт покажет список редакций и спросит номер. Без `-IsoPath` он работает в пошаговом режиме, как через `Start.cmd`. Итоговый ISO по умолчанию появится рядом с исходным, в имени версия LunqDebloater (`Win11_26H2_Lunq_1.13.0.iso`). В пошаговом режиме после сводки скрипт спросит своё имя, Enter оставит это. Лог запуска будет в папке `Logs` рядом со скриптом (см. «Логи и версия»).

| Параметр | Назначение |
|---|---|
| `-IsoPath` | Исходный ISO. Без него включается пошаговый режим |
| `-OutputIso` | Полный путь к итоговому ISO, берётся как есть, без версии |
| `-OutputName` | Имя итогового ISO рядом с исходным, без `.iso`: к нему добавится версия LunqDebloater, например `-OutputName Office` даст `Office_1.13.0.iso`. Вместе с `-OutputIso` не указывается |
| `-ConfigPath` | Папка с настройками вместо `Config` рядом со скриптом |
| `-ProfilePath` | Свой JSON-профиль вместо `Config\Profile.json` |
| `-SkipCategory` | Id категорий профиля, которые нужно пропустить, через запятую |
| `-Index` / `-Edition` | Редакция по номеру или имени |
| `-WorkDir` | Рабочая папка. Скрипт очищает её целиком, поэтому подойдёт только новая или пустая папка (или созданная им раньше), но не корень диска и не папка с ISO. Доступ к ней есть только у администраторов |

## Как устроен процесс

1. ISO монтируется, его содержимое копируется в рабочую папку.
2. Выбранная редакция экспортируется в отдельный `install.wim` (ESD при этом конвертируется в WIM).
3. `install.wim` монтируется, в него встраиваются обновления и драйверы (если выбраны), при желании обновляется WinRE и добавляется скрипт первого входа. В корень ISO кладётся файл ответов, если он включён. Затем применяется профиль: Appx, компоненты, реестр.
4. Образ сохраняется. Если выбрано, обновляется установщик: в `sources` распаковывается Setup Dynamic Update, обслуживается `boot.wim`, и из него копируются `setup.exe`, `setuphost.exe` и загрузчик UEFI. Если для `boot.wim` нет ни обновлений, ни драйверов, он не трогается. Затем `install.wim` пересжимается, и `oscdimg` собирает загрузочный ISO.

Все шаги по порядку и условия, при которых они выполняются, описаны в [ARCHITECTURE.md](ARCHITECTURE.md#шаги-сборки).

При ошибке образ отключается без сохранения, а кусты реестра выгружаются.

## Логи и версия

Каждый запуск пишет лог в папку `Logs` рядом со скриптом, с самого старта: в него попадают и ошибки при выборе ISO, профиля и проверке системы. В первых строках лога указаны версия LunqDebloater, версия Windows и PowerShell и параметры запуска. Рядом лежит подробный лог DISM: если DISM выдал ошибку, настоящая причина обычно видна только в нём. Со встраиванием обновлений он вырастает до сотен мегабайт, поэтому в конце запуска сжимается в `LunqDebloater_<дата>_dism.zip` (открывается двойным щелчком). Хранятся логи последних 10 запусков и логи DISM последних 3, более старые удаляются сами. Путь к логу показывается в плане сборки, в итоге и при ошибке.

У заголовка каждого шага стоит время его начала, а итог показывает три самых долгих шага. В логе DISM перед каждым шагом есть метка `===== LunqDebloater <время>: step N/M: <шаг> =====`, по ней удобно искать нужное место. Если внешняя программа (например, robocopy или oscdimg) завершилась с ошибкой, в лог попадают последние строки её вывода. При ошибке под её текстом видно, где именно она произошла.

Если сборка прервалась ошибкой, рядом с логом появляется архив `LunqDebloater_<дата>_report.zip` с логом запуска, логом DISM и профилем. Путь к папке пользователя, имя пользователя и имя компьютера в нём заменены, так что для отчёта достаточно приложить этот архив. Лог DISM больше 20 МБ в нём сокращён: все ошибки, предупреждения и метки шагов и последние 20 000 строк. Если архива нет, пришлите оба файла последнего запуска: `LunqDebloater_<дата>.log` и `LunqDebloater_<дата>_dism.zip`.

Версия LunqDebloater видна в заголовке окна, в начале лога, в итоге сборки и в имени итогового ISO (если его путь не задан через `-OutputIso`). Она же записывается в собранный образ вместе с настройками сборки. На установленной системе их можно посмотреть так:

```powershell
reg query HKLM\SOFTWARE\LunqDebloater
```

Там указаны версия и дата сборки, исходный ISO и редакция, файл ответов, профиль, включённые и пропущенные категории, встроенные обновления (в том числе Safe OS и Setup Dynamic Update), число драйверов, обновлялись ли установщик и WinRE, очистка хранилища, пропущенные шаги, программы и скрипты после установки. Если после установки что-то работает не так, по этим данным видно, чем и с какими настройками собран образ.

## Обновления

1. Скачайте накопительное обновление для своей версии из [каталога Центра обновления Майкрософт](https://www.catalog.update.microsoft.com), например по запросу `Windows 11 Version 26H2 x64`. Если в каталоге для него несколько файлов, скачайте все.
2. В пошаговом режиме выберите папку с ними в сводке пунктом «Выбрать папку с обновлениями», например «Загрузки». Или положите файлы в `Config\Updates`: тогда они сразу появятся в сводке, а с параметрами встроятся сами (если не нужно, добавьте `-SkipUpdates`). Другую папку с параметрами задаёт `-UpdatesPath`.

Обновления Safe OS и Setup Dynamic Update каталог показывает в том же поиске, что и накопительное, но они для среды восстановления и установщика, в саму систему не встанут. В `Config\Updates` для них есть подпапки:

- `Config\Updates\SafeOS`: Safe OS Dynamic Update (`.cab`), ставится в WinRE после накопительного обновления;
- `Config\Updates\Setup`: Setup Dynamic Update (`.cab`), распаковывается в `sources` ISO и обновляет файлы установщика.

В папке, выбранной в сводке или через `-UpdatesPath`, ищутся такие же подпапки. Если их нет, например в «Загрузках», Dynamic Update можно оставить рядом с остальными обновлениями: скрипт узнаёт их по содержимому `.cab`. В Setup Dynamic Update нет пакета DISM (файла `.mum`), а Safe OS Dynamic Update называется `Package_for_SafeOSDU`. Сводка помечает такие файлы. Они встраиваются только вместе с обновлением установщика и WinRE (см. «Установщик и среда восстановления»). Берите их для той же версии Windows, что и накопительное обновление.

Обновления ставятся сразу после монтирования образа, до удаления приложений и компонентов. Порядок как у Microsoft: сначала пакеты без номера KB (языковые пакеты и компоненты по запросу), затем обновления Windows по возрастанию номера KB, последними обновления .NET (`ndp` в имени). Накопительное обновление ставится долго (10-30 минут) и требует дополнительного места. После обновлений имеет смысл включить `-CleanupComponents` (в сводке это пункт под скачиванием обновлений, он работает и для папки с обновлениями, и для скачанных): старые версии системных файлов удалятся, и образ станет меньше.

## Драйверы

1. Если ISO собирается для этого же компьютера, выберите в сводке пункт «Взять драйверы с этого компьютера»: скрипт выгрузит сторонние драйверы текущей Windows. Для другого компьютера выберите пунктом «Выбрать папку с драйверами» папку с распакованными драйверами (файлы `.inf` вместе с `.sys`, `.cat` и остальными, подпапки любые), например флешку с драйверами производителя. Можно и положить их в `Config\Drivers`, а с параметрами указать папку через `-DriversPath`. Как распаковать драйверы, описано в [Config/README.txt](Config/README.txt).
2. Драйверы появятся в сводке перед сборкой, а с параметрами встроятся сами (если не нужно, добавьте `-SkipDrivers`).
3. Если установщик не видит диск (контроллеры Intel RST/VMD, RAID), добавьте драйверы и в него: в сводке это пункт в разделе «Драйверы», с параметрами нужен ключ `-DriversToSetup`. Тогда драйверы попадут и в среду восстановления (WinRE), и она тоже увидит диск. Туда добавляются только драйверы контроллеров дисков (класс `SCSIAdapter` или `HDC` в `.inf`): установщик при загрузке целиком распаковывается в память, и все драйверы сразу сильно замедлили бы её.

Драйверы попадают в хранилище драйверов образа, и Windows сама ставит подходящие во время установки. Каждый `.inf` добавляется отдельно, поэтому неподходящий драйвер не срывает сборку, а попадает в итог как ошибка. Драйвер в виде `.exe` без `.inf` встроить нельзя, его сначала нужно распаковать.

Это хорошо сочетается с категорией `drivers` профиля (по умолчанию выключена): она запрещает Windows Update ставить свои драйверы, а нужные вы встраиваете сами.

## Установщик и среда восстановления

Кроме самой системы в ISO есть ещё два образа на базе Windows PE:

- **установщик** (`sources\boot.wim`, образ 2), с которого загружается флешка;
- **среда восстановления** (WinRE, `Windows\System32\Recovery\Winre.wim` внутри системы), которая открывается при сбое загрузки и через «Параметры → Восстановление».

По умолчанию они остаются такими, как в ISO. С `-UpdatesToSetup` в них встраиваются те же обновления Windows, что и в систему, а с `-DriversToSetup` драйверы контроллеров дисков. В сводке перед сборкой это пункты под обновлениями и драйверами; если нашлись Safe OS или Setup Dynamic Update, пункт обновления установщика включён сразу. С `-UpdatesToSetup` в WinRE ставится и Safe OS Dynamic Update, а в `sources` ISO распаковывается Setup Dynamic Update. После обновления установщика `setup.exe` и `setuphost.exe` из `boot.wim` копируются в `sources` ISO: по инструкции Microsoft они должны совпадать с файлами в `boot.wim`, иначе установка может не запуститься. Оттуда же берётся загрузчик UEFI на ISO (`efi\boot\bootx64.efi` и `bootmgr.efi`) и `efi\microsoft\boot\efisys.bin`, из которого `oscdimg` делает загрузочный образ UEFI: ISO, подключённый напрямую, грузится тем же загрузчиком, что и флешка из него. Обновления .NET и прочие пакеты, которые не ставятся в Windows PE, пропускаются. После обновлений оба образа очищаются от старых файлов и пересжимаются. Сборка с обновлениями займёт на 10-20 минут дольше.

### Загрузчик и Secure Boot

Microsoft меняет сертификат, которым подписан загрузчик Windows (уязвимость BlackLotus, CVE-2023-24932): старый Windows Production PCA 2011 постепенно отзывается, новый называется Windows UEFI CA 2023. Обычный ISO грузится старым загрузчиком и не загрузится с включённым Secure Boot на компьютере, где старый сертификат уже попал в список отозванных (DBX).

С `-BootCA2023` (пункт в разделе «Дополнительно» сводки) на ISO кладётся загрузчик, подписанный новым сертификатом: файлы `_EX` из обновлённого образа (`Windows\Boot\EFI_EX`, `DVD_EX` и `Fonts_EX`) вместо `efi\boot\bootx64.efi`, `bootmgr.efi`, `efisys.bin` и шрифтов загрузчика. Для этого нужно накопительное обновление в папке обновлений или `-DownloadUpdates`, а установщик обновляется вместе с системой, как требует Microsoft. Если в образе нет файлов `_EX`, на ISO остаётся обычный загрузчик, а итог об этом предупреждает.

Такой носитель, наоборот, не загрузится с включённым Secure Boot на компьютере, где в базе DB нет сертификата Windows UEFI CA 2023: обычно это компьютеры до 2024 года без свежих обновлений прошивки и Windows. Если не уверены, оставьте обычный загрузчик.

## Флешка FAT32

Флешка для загрузки через UEFI обычно отформатирована в FAT32, а на FAT32 не помещаются файлы больше 4 ГБ. Со свежими обновлениями и драйверами `install.wim` бывает больше, и тогда итог сборки об этом предупреждает. Есть два пути:

- записать ISO через [Rufus](https://rufus.ie): он сам справится с большим `install.wim`;
- собрать ISO с `-SplitWim` (пункт в разделе «Дополнительно» сводки): `install.wim` делится на части `install.swm`, `install2.swm` и так далее по 3800 МБ, и ISO можно просто скопировать на флешку FAT32. Установщик Windows сам собирает части.

## После установки

Можно сделать так, чтобы при первом входе в установленную Windows поставились нужные программы и выполнились ваши скрипты:

1. В `Config\Apps.txt` уже есть готовый список: 7-Zip, DirectX и все версии Visual C++ Redistributable, которые нужны играм и многим программам. Добавьте свои программы (Id из winget, по одному в строке) или закомментируйте ненужные через `#`. В конце файла есть ещё примеры.
2. Если нужно, положите в `Config\Scripts` свои скрипты `*.ps1`. Они выполнятся после программ, по порядку имён, с правами администратора. Остальные файлы из этой папки тоже копируются, и скрипты могут ими пользоваться.
3. Программы и скрипты появятся в сводке перед сборкой, а с параметрами добавятся сами (если не нужно, добавьте `-SkipApps` или `-SkipScripts`).

При первом входе откроется окно с ходом работы. Скрипт дождётся интернета и winget, тихо поставит программы для всех пользователей (`--scope machine`, а если у программы нет такого установщика, для текущего), выполнит скрипты, каждый в отдельном процессе PowerShell, и закроет окно. Если интернета нет, программа не поставилась или окно закрыли на середине, недоделанное повторится при следующем входе (до 5 попыток). Пока программы не поставились, скрипты ждут: они выполнятся после программ или на последней попытке. Скрипт с ошибкой повторно не запускается, а скрипт, который дважды начался и не дошёл до конца (например, перезагрузил компьютер), пропускается. Если последняя попытка не дошла до конца, на следующем входе скрипт только убирает за собой. Ваши скрипты, сети Wi-Fi и лог доступны только администраторам: папки закрываются уже при сборке образа, поэтому они закрыты и тогда, когда окно UAC при первом входе отклонили. В самом ISO и на флешке они лежат открыто внутри `install.wim`: кто получит ISO, сможет их прочитать, поэтому не отдавайте другим ISO с паролями в скриптах. Когда всё сделано, копии ваших скриптов и всё, что лежало рядом с ними, удаляются с диска: там могут быть пароли и ключи. Остаются только `Apps.txt` и лог `C:\Windows\Setup\Scripts\Lunq\FirstLogon.log`. Подробности в [Config/README.txt](Config/README.txt).

Скрипты можно сохранять в любом редакторе. Windows PowerShell 5.1 читает файл в UTF-8 без метки BOM как ANSI, и русский текст в кавычках ломает весь скрипт. Поэтому при сборке такие файлы пересохраняются в UTF-8 с BOM, это видно в выводе шага.

Скрипт считается неудачным, если он выбросил ошибку или завершился с кодом выхода не 0. Код выхода берётся и от последней внешней программы в скрипте: например, robocopy возвращает 1 и при успехе. Если так и задумано, допишите в конце скрипта `exit 0`.

Если записываете флешку через Rufus, не отмечайте в его окне ни одну настройку Windows, в том числе обход требований TPM, Secure Boot и памяти. Для них Rufus добавляет свой файл ответов, Windows берёт его вместо файла LunqDebloater, и программы со скриптами после установки сами не запустятся. Обход требований и локальную учётную запись лучше включить в файле ответов LunqDebloater (см. «Файл ответов»). Если без настроек Rufus или своего `autounattend.xml` всё же не обойтись, после установки запустите всё вручную из PowerShell от имени администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Windows\Setup\Scripts\Lunq\FirstLogon.ps1
```

## Файл ответов

Файл ответов (`autounattend.xml` в корне ISO) отвечает за человека на часть вопросов установки Windows. Windows Setup находит его на флешке сама. В пошаговом режиме он включён по умолчанию (пункты под «Файл ответов» в сводке), с параметрами включается ключом `-Unattend`.

| Пункт сводки | Ключ | Что делает |
|---|---|---|
| Не спрашивать про лицензию и конфиденциальность | `-Unattend` | Лицензия принимается сама, все параметры конфиденциальности (диагностика, реклама, местоположение) выключены, страница с ними не показывается |
| Язык, регион и часовой пояс как на этом компьютере | `-Unattend` | Язык установщика и Windows берётся из образа, а формат, раскладки клавиатуры и часовой пояс с компьютера, на котором собирается ISO |
| Обойти требования Windows 11 | `-BypassRequirements` | Установка не проверяет TPM 2.0, Secure Boot и объём памяти. Для компьютеров, на которые Windows 11 иначе не ставится |
| Локальная учётная запись | `-LocalAccount`, `-LocalAccountName` | С `-LocalAccountName` учётная запись администратора с этим именем создаётся при установке, и экран учётной записи не показывается. В пошаговом режиме имя спрашивается после сводки, по умолчанию имя пользователя этого компьютера. Пароля в ISO нет: при первом входе окно первичной настройки предложит его задать (Enter оставит без пароля). Пока пароль не задан, войти может любой, кто сидит за компьютером. Без имени Windows не предлагает войти в учётную запись Майкрософт и сразу спрашивает имя и пароль локальной. Для надёжности в файл ответов добавляется и `BypassNRO`: если экран входа всё же появится, на шаге подключения к сети можно выбрать «У меня нет Интернета» и создать локальную учётную запись |

Диск для установки, ключ продукта (можно нажать «У меня нет ключа») и сеть по-прежнему выбираются вручную: файл ответов ничего не стирает сам. Пароли в нём не хранятся, имя и пароль учётной записи вводятся при установке. Если в образе есть программы или скрипты после установки, их команда тоже записывается в этот файл.

С Rufus не отмечайте настройки Windows в его окне: он добавит свой файл ответов вместо этого. Работу файла ответов на настоящей установке стоит проверить в виртуальной машине: сборка проверялась только на заглушках.

## Что в образе

Чтобы составить свой профиль, полезно знать точные имена приложений и компонентов в своей редакции. В пошаговом режиме выберите в начале «Посмотреть, что есть в образе», а с параметрами добавьте `-ListContents`:

```powershell
.\LunqDebloater.ps1 -IsoPath D:\Win11.iso -Edition "Windows 11 Pro" -ListContents
```

Скрипт ничего не собирает и не меняет. Он копирует редакцию в рабочую папку, открывает её только для чтения и сохраняет рядом с ISO файл `<имя ISO>_<номер редакции>_contents.txt`. В файле перечислены приложения Appx, установленные компоненты (Capabilities) и функции Windows (включённые и выключенные). Справа у каждого элемента указаны категории профиля, которые его уже удаляют. В конце файла собраны записи профиля, которых нет в образе. Для этого режима Windows ADK не нужен.

## Свежие обновления каждый месяц

Вместо того чтобы искать накопительное обновление в каталоге вручную, включите в сводке пункт «Скачать свежие обновления из каталога Microsoft» или добавьте `-DownloadUpdates`. Когда редакция выбрана и известны её выпуск (например, 26H2) и архитектура, скрипт сам находит в [каталоге Центра обновления Майкрософт](https://www.catalog.update.microsoft.com) последнее накопительное обновление и обновление .NET, а вместе с обновлением установщика (`-UpdatesToSetup`, в пошаговом режиме включается само) ещё Safe OS и Setup Dynamic Update. Предварительные (Preview) и серверные обновления не берутся. Файлы скачиваются только с серверов загрузки Microsoft, проверяются по контрольной сумме из каталога (файл без суммы не скачивается) и хранятся в `Config\Updates\Catalog\<выпуск>-<архитектура>`: при следующей сборке уже скачанное не скачивается снова, а обновления прошлого месяца удаляются. Обновления из `Config\Updates` встраиваются вместе со скачанными. Setup Dynamic Update, скачанный или свой, распаковывается в установщик, только если он подписан Microsoft.

У каталога нет официального API: скрипт читает ту же страницу, что видит браузер. Если Microsoft её изменит, скрипт скажет, что ничего не нашёл, и обновление можно будет скачать вручную, как раньше.

Собранный со скачиванием ISO можно пересобирать каждый месяц без вашего участия. В пошаговом режиме скрипт предложит это в конце сборки, а с параметрами задание создаётся по рецепту (см. ниже):

```powershell
.\LunqDebloater.ps1 -Recipe D:\Win11_26H2_Lunq_1.13.0.lunq.json -Schedule Monthly   # каждый месяц 15-го числа
.\LunqDebloater.ps1 -Recipe D:\Win11_26H2_Lunq_1.13.0.lunq.json -Schedule Off       # больше не пересобирать
```

Задание `LunqDebloater\<имя ISO без версии>-<отпечаток пути рецепта>` в планировщике запускается от имени системы 15-го числа (накопительные обновления выходят во второй вторник месяца) и, если компьютер был выключен, при следующем включении. Оно повторяет сборку по рецепту со свежими обновлениями и перезаписывает итоговый ISO. Задание запускает не папку программы, которую может поменять любая программа пользователя, а копию LunqDebloater, `Config` и рецепта в `C:\Program Files\LunqDebloater-Schedule\<имя задания>`: менять её могут только администраторы. Лог такого запуска лежит в `Logs` этой копии. После обновления LunqDebloater или правки `Config` запустите `-Schedule Monthly` ещё раз, чтобы обновить копию. Рецепт можно взять и от сборки новой версией: задание у ISO одно, оно заменится, а не появится второе. Новая версия собирает ISO с новым именем, а ISO прошлой версии остаётся, удалите его сами, если он не нужен; `-Schedule Off` удаляет задание вместе с копией.

## Рецепт сборки и отчёт

После каждой сборки рядом с итоговым ISO появляются два файла:

- `<имя ISO>.lunq.json`, рецепт: исходный ISO с контрольной суммой, редакция, профиль целиком, включённые категории, пункты сводки, обновления с контрольными суммами, драйверы, программы и настройки файла ответов;
- `<имя ISO>.lunq.html`, отчёт «до и после»: сколько приложений, компонентов и функций было в редакции и сколько убрано, что сделано по каждой категории профиля, что не удалось и сколько шёл каждый шаг. Это один файл без внешних ссылок, его можно открыть в любом браузере и переслать.

`-Recipe` повторяет сборку по рецепту без вопросов:

```powershell
.\LunqDebloater.ps1 -Recipe D:\Win11_26H2_Lunq_1.13.0.lunq.json -Force
```

Параметры командной строки важнее рецепта: например, `-IsoPath` соберёт то же самое из нового ISO, а `-SkipUpdates` без обновлений. Если профиль с тех пор изменился или пропал, берётся его копия из рецепта. Если обновления в папке отличаются от записанных в рецепте, скрипт предупредит об этом перед сборкой.

## Этот компьютер без ISO и откат

Профиль можно применить и к уже установленной Windows, на которой запущен скрипт: в пошаговом режиме это пункт «Применить профиль к этому компьютеру» в начале, с параметрами `-Online`. Выполняются те же шаги профиля, что и в образе: удаление приложений (у новых и уже существующих пользователей), компонентов и функций и запись реестра (в профиль `Default` и текущему пользователю). ISO и Windows ADK для этого не нужны. `-Category` применяет только перечисленные категории:

```powershell
.\LunqDebloater.ps1 -Online -Category telemetry,ads
```

Перед каждым изменением скрипт запоминает, как было, в `C:\Windows\LunqDebloater\Restore.json`. Тот же файл кладётся и в каждый собранный образ, поэтому откат работает и на Windows, установленной с ISO LunqDebloater. Вернуть убранное можно пунктом «Вернуть то, что убрал LunqDebloater» или ключом `-Restore` (с `-Category`, чтобы вернуть только часть):

```powershell
.\LunqDebloater.ps1 -Restore
```

Записи реестра возвращаются к прежним значениям, удалённые ключи восстанавливаются целиком, компоненты и функции ставятся снова. Приложение возвращается, если его файлы ещё на диске; удалённое из образа вместе с файлами придётся поставить из Microsoft Store, скрипт покажет ссылки на его страницы. Системные пакеты (CBS) обратно не ставятся. Всё, что не вернулось, остаётся в файле, и `-Restore` можно запустить ещё раз. После отката перезагрузите компьютер.

## Копия этого компьютера

Если ISO собирается, чтобы переустановить Windows на этом же компьютере, в образ можно взять то, что уже есть здесь:

| Пункт сводки | Ключ | Что делает |
|---|---|---|
| Взять драйверы с этого компьютера | `-HostDrivers` | Выгружает сторонние драйверы этой Windows и встраивает их в образ (см. «Драйверы») |
| Программы этого компьютера | `-HostApps` | Берёт список программ через `winget export` и ставит их при первом входе вместе с `Apps.txt`. Программы, которых winget не знает, не попадут в список. `Config\Apps.txt` при этом не меняется |
| Сети Wi-Fi этого компьютера | `-HostWifi` | Сохраняет профили Wi-Fi (`netsh wlan export key=clear`) и добавляет их при первом входе, ещё до установки программ |

Пароли сетей Wi-Fi лежат в ISO открытым текстом, пока Windows не установлена и в неё не вошли: при первом входе добавленный профиль сразу удаляется с диска. Профиль, который не добавился (например, драйвер Wi-Fi ещё не стоит), ждёт следующего входа в папке, доступной только администраторам, и удаляется, когда первичная настройка закончена. Поэтому этот пункт по умолчанию выключен, а такой ISO нельзя никому отдавать.

## Профиль

Всё, что удаляется и меняется, описано в `Config\Profile.json`. Правьте его под себя или положите рядом ещё профили (`*.json`): тогда скрипт спросит, какой взять. Профиль состоит из категорий: в каждой собрано всё, что относится к одной теме (приложения, компоненты, функции и реестр), и её можно целиком включить или выключить.

```jsonc
{
  "$schema": "../Schemas/Profile.schema.json",   // подсказки и проверка в VS Code
  "Name": "Default",
  "Description": "Что делает профиль",
  "Options": { "RemoveFeaturePayload": false },   // удалять ли файлы отключённых функций
  "Categories": [
    {
      "Id": "ai",                                 // короткое имя для -SkipCategory
      "Name": { "ru": "Copilot и ИИ", "en": "Copilot and AI" },
      "Enabled": true,                            // false: категория пропускается
      "Description": "Что делает категория",
      "Appx":         ["Microsoft.Copilot"],      // DisplayName, можно с *
      "Capabilities": [],                         // Get-WindowsCapability, можно с *
      "Features":     ["Recall"],                 // Get-WindowsOptionalFeature
      "Packages":     [],                         // CBS-пакеты, осторожно
      "Uninstall":    [],                         // программы, которые удаляет первый вход: MicrosoftEdge
      "Registry": [
        { "Hive": "SOFTWARE", "Path": "Policies\\Microsoft\\Windows\\WindowsCopilot", "Name": "TurnOffWindowsCopilot", "Type": "REG_DWORD", "Value": 1 },
        { "Hive": "DefaultUser", "Path": "Software\\Microsoft\\Windows\\CurrentVersion\\Run", "Name": "OneDriveSetup", "Action": "DeleteValue" },
        { "Hive": "SOFTWARE", "Path": "Microsoft\\WindowsUpdate\\Orchestrator\\UScheduler_Oobe\\OutlookUpdate", "Action": "DeleteKey" }
      ]
    }
  ]
}
```

Пустые списки в категории можно не писать.

Тексты `Name` и `Description` (у профиля, категорий и записей реестра) можно писать строкой или переводами: `{ "ru": "...", "en": "..." }`. Скрипт берёт язык интерфейса, затем английский. Строка `"$schema"` подключает схему [Schemas/Profile.schema.json](Schemas/Profile.schema.json): по ней VS Code подсказывает поля и подчёркивает ошибки.

### Требования к версии Windows

Профиль может указать, на какую сборку Windows он рассчитан:

```json
"Requirements": { "Build": 26300, "MinRevision": 9457, "Architecture": "amd64" }
```

- `Build`: номер сборки должен совпадать точно (26300 соответствует 26H2, 26200 соответствует 25H2, 26100 соответствует 24H2).
- `MinRevision`: минимальная ревизия, то есть число после точки в `26300.9457`. Всё, что новее, подходит, так что профиль не нужно править после каждого ежемесячного обновления.
- `Architecture`: `amd64` или `arm64`.

Скрипт сверяет это с выбранной редакцией сразу после чтения ISO, ещё до копирования файлов. Если сборка не подходит, он останавливается и подсказывает, где скачать свежий ISO. Если не хватает только ревизии, а в папке обновлений есть накопительное обновление Windows, скрипт лишь предупреждает: обновление поднимет ревизию. Чтобы собрать образ на другой сборке сознательно, запустите скрипт с `-SkipVersionCheck`. Если блока `Requirements` в профиле нет, проверка не выполняется. Профиль старого формата (с `Appx`, `Registry` и т.д. на верхнем уровне, без `Categories`) тоже работает: он считается одной категорией.

Категории в `Profile.json`:

| Id | Категория |
|---|---|
| `apps` | Встроенные приложения |
| `legacy` | Устаревшие компоненты |
| `telemetry` | Телеметрия и диагностика |
| `ai` | Copilot и ИИ |
| `ads` | Реклама и предложения |
| `search` | Поиск и Bing |
| `store` | Microsoft Store |
| `drivers` | Драйверы из Windows Update |
| `onedrive` | OneDrive |
| `edge` | Microsoft Edge (по умолчанию выключена) |

Пропустить категории без правки профиля: `-SkipCategory drivers,store`. В пошаговом режиме скрипт показывает список категорий, и их можно включать и выключать по номерам.

Записи реестра:

- `Hive`: `SOFTWARE` (HKLM\SOFTWARE), `SYSTEM` (HKLM\SYSTEM, используйте `ControlSet001` вместо `CurrentControlSet`) или `DefaultUser` (HKCU для всех новых пользователей).
- `Name`: имя значения. Если не указать, запись относится к значению «по умолчанию» у ключа.
- `Action`: `Set` (по умолчанию), `DeleteValue` или `DeleteKey`.
- `Type`: `REG_DWORD`, `REG_QWORD` (число или строка `"0x..."`), `REG_SZ`, `REG_EXPAND_SZ`, `REG_MULTI_SZ` (массив строк), `REG_BINARY` (hex-строка, например `"de ad be ef"`).
- `Value`: значение. Строки записываются как есть, с кавычками и `\` в конце.
- `Description`: пояснение, необязательно. Скрипт его не использует, оно для людей и для будущего GUI.

Ошибку в записи (неизвестный тип или действие, не число в `REG_DWORD`) скрипт покажет сразу при чтении профиля, ещё до сборки.

Узнать точные имена в своём образе проще всего режимом «Что в образе» (см. выше). Вручную это можно сделать так (после `Mount-WindowsImage`):

```powershell
Get-AppxProvisionedPackage -Path C:\LunqWork\mount | Select DisplayName
Get-WindowsCapability     -Path C:\LunqWork\mount | Where State -eq Installed | Select Name
Get-WindowsOptionalFeature -Path C:\LunqWork\mount | Where State -eq Enabled | Select FeatureName
```

Категория `drivers` отключает загрузку драйверов из Windows Update и по умолчанию выключена. Если в системе нет встроенного драйвера сетевой карты или Wi-Fi, после установки не будет интернета, и драйвер придётся ставить вручную. Включайте её (`"Enabled": true` в профиле или по номеру в пошаговом режиме), только если встраиваете нужные драйверы в образ сами (см. раздел «Драйверы»).

Категория `edge` удаляет Microsoft Edge скриптом [EdgeRemover](https://github.com/he3als/EdgeRemover) от he3als (лежит без изменений в `ThirdParty\EdgeRemover`). Средствами DISM Edge из образа не убрать, поэтому в собранной Windows его удаляет первый вход, после программ из `Apps.txt`, а `-Online` удаляет его сразу. WebView2 остаётся: без него не работают многие программы. `-Restore` ставит Edge обратно, для этого нужен интернет. Категория по умолчанию выключена: включайте её (`"Enabled": true` в профиле или по номеру в пошаговом режиме), только если в `Apps.txt` есть другой браузер, иначе после установки браузера не останется.

Профиль по умолчанию не трогает Microsoft Store, App Installer (winget), Терминал, Фотографии, Калькулятор, Блокнот и Безопасность Windows. Списки `Packages` пусты намеренно: удаление CBS-пакетов может сломать установку обновлений.

## Разработка

Код разложен так:

| Путь | Что там |
|---|---|
| `LunqDebloater.ps1` | Сам скрипт: параметры, перезапуск, права администратора, лог и уборка после сборки. Режимы, сводка и план лежат в модуле (`Modes`) |
| `Install.ps1` | Загрузчик для запуска одной командой (`irm ... \| iex`) |
| `Modules\LunqDebloater\` | Модуль с функциями. Версия задаётся в манифесте `LunqDebloater.psd1` |
| `Modules\LunqDebloater\Private\` | Функции по темам: `Console`, `Language`, `Profile`, `Iso`, `Checks`, `Image`, `Servicing`, `Removal`, `Registry`, `PostInstall`, `Unattend`, `Inventory`, `Options` (сводка «Что войдёт в образ»), `Modes` (режимы скрипта), `Build` (шаги сборки), `Report`, `System`, `Catalog`, `Schedule`, `Recipe`, `Restore`, `Uninstall`, `Host` |
| `Modules\LunqDebloater\Data\Releases.psd1` | Выпуски Windows начиная с 24H2: сборки, названия и пакеты включения |
| `Modules\LunqDebloater\Strings\` | Тексты интерфейса: `ru\*.psd1` и `en\*.psd1` |
| `Modules\FirstLogon\FirstLogon.ps1` | Скрипт первого входа, который кладётся в образ |
| `Schemas\Profile.schema.json` | JSON-схема профиля |
| `Tests\` | Тесты Pester и заглушка модуля DISM |

Тесты не трогают систему: вместо DISM, reg.exe, oscdimg и winget работают заглушки, а сборка идёт в папке теста. Запустить их и анализатор (нужны Pester 5 и PSScriptAnalyzer):

```powershell
Install-Module Pester -MinimumVersion 5.5.0 -MaximumVersion 5.99.99 -Scope CurrentUser -Force -SkipPublisherCheck
Install-Module PSScriptAnalyzer -MinimumVersion 1.23.0 -Scope CurrentUser -Force
Invoke-Pester -Path .\Tests
Invoke-ScriptAnalyzer -Path .\LunqDebloater.ps1 -Settings .\PSScriptAnalyzerSettings.psd1
Invoke-ScriptAnalyzer -Path .\Install.ps1 -Settings .\PSScriptAnalyzerSettings.psd1
Invoke-ScriptAnalyzer -Path .\Modules -Recurse -Settings .\PSScriptAnalyzerSettings.psd1
```

То же самое GitHub Actions выполняет для каждого PR. Что поменялось в каждой версии, записано в [CHANGELOG.md](CHANGELOG.md).

Подробно устройство кода, порядок шагов сборки и тесты описаны в [ARCHITECTURE.md](ARCHITECTURE.md). Как предложить изменение и сообщить об ошибке, описано в [CONTRIBUTING.md](.github/CONTRIBUTING.md), об уязвимости в [SECURITY.md](.github/SECURITY.md). Правила для ИИ-помощников (Claude Code, Codex, Copilot) лежат в [AGENTS.md](AGENTS.md). Схема профиля лежит в `Schemas\Profile.schema.json`; `.vscode\settings.json` подключает её к профилям в папках `Config*`, так что VS Code подсказывает поля профиля и проверяет их даже без интернета.
