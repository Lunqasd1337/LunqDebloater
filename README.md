# LunqDebloater

PowerShell-скрипт для преднастройки ISO-образа Windows 11 перед установкой. Работает офлайн, через DISM, над `install.wim`:

- удаляет предустановленные Appx-приложения;
- удаляет компоненты Windows (Capabilities и Optional Features);
- по желанию встраивает обновления (`.msu`, `.cab`), чтобы Windows была свежей сразу после установки;
- по желанию встраивает драйверы (`.inf`), чтобы Windows сразу ставилась с драйверами под ваше железо;
- по желанию обновляет установщик и среду восстановления (WinRE) теми же обновлениями и драйверами, а также Safe OS и Setup Dynamic Update;
- по желанию ставит программы через winget и выполняет ваши скрипты при первом входе в Windows;
- по желанию кладёт в ISO файл ответов: установка спрашивает меньше, а на старых компьютерах можно обойти требования TPM и Secure Boot;
- вносит изменения в реестр образа (кусты `SOFTWARE`, `SYSTEM` и профиль `Default`, от которого создаются все новые пользователи).

На выходе получается загрузочный ISO (BIOS + UEFI, для ARM64 только UEFI) с одной выбранной редакцией. Отдельный режим «Что в образе» ничего не собирает, а выгружает список приложений и компонентов редакции, чтобы было проще составить свой профиль.

Собирать можно в консоли, по шагам или с параметрами, или в окне `LunqDebloater.exe`, где все настройки на одной странице (см. «Окно»).

## Ответственность

LunqDebloater меняет установочный образ Windows так, как Microsoft официально не поддерживает: удаляет приложения и компоненты и правит реестр. **Всё, что вы делаете с его помощью, вы делаете на свой страх и риск.** Автор не отвечает за потерю данных, неработающую или нестабильную систему, проблемы с обновлениями, активацией, гарантией или поддержкой производителя.

- Будущие накопительные обновления Windows могут не установиться или вернуть удалённое, если рассчитаны на вырезанные компоненты.
- Перед установкой на рабочий компьютер проверьте собранный ISO в виртуальной машине и сохраните важные данные.

Программа распространяется «как есть», без каких-либо гарантий (см. [LICENSE](LICENSE)).

## Требования

- Windows 11 и Windows PowerShell 5.1 (встроен в Windows). Если запустить скрипт из PowerShell 7, он сам перезапустится в 5.1: в PowerShell 7 командлеты DISM для Appx падают с ошибкой «Класс не зарегистрирован».
- Лучше собирать на Windows 11 той же версии, что и ISO, или новее. Модуль DISM берётся из системы, и DISM старой системы, особенно Windows 10, может не справиться со свежими обновлениями нового образа. Скрипт предупредит, если система старше образа.
- [Windows ADK](https://learn.microsoft.com/windows-hardware/get-started/adk-install), компонент **Deployment Tools** (нужен только `oscdimg.exe`).
- Около 25 ГБ свободного места на NTFS-диске для рабочей папки (по умолчанию `C:\LunqWork`), с обновлениями и драйверами больше: ещё три размера обновлений и два размера драйверов. Точную цифру покажет проверка перед сборкой.
- Оригинальный ISO Windows 11.
- Для окна `LunqDebloater.exe`: WebView2 Runtime (в Windows 11 уже есть).

Скрипт сам проверит права администратора, наличие ADK и свободное место ещё до начала сборки и подскажет, что исправить.

## Папка Config

Все настройки лежат в одной папке `Config` рядом со скриптом. Ничего не нужно искать по разным папкам: что положили в `Config`, то и попадёт в образ.

| Что | Для чего |
|---|---|
| `Profile.json` | Что удалить из Windows и какие настройки реестра внести (см. «Профиль») |
| `Apps.txt` | Программы, которые поставятся через winget при первом входе (см. «После установки») |
| `Scripts\` | Ваши скрипты `*.ps1`, которые выполнятся после установки |
| `Drivers\` | Драйверы `.inf`, можно в подпапках (см. «Драйверы») |
| `Updates\` | Обновления `.msu`/`.cab`, в подпапках `SafeOS\` и `Setup\` обновления для WinRE и установщика (см. «Обновления») |

Подсказка по каждому пункту лежит в [Config/README.txt](Config/README.txt). Драйверы и обновления в git не попадают.

Перед сборкой скрипт показывает сводку «Что войдёт в образ»: что нашлось в `Config`, с номерами. Лишнее можно выключить по номеру, ничего не удаляя из папки. Там же включается очистка хранилища компонентов, добавление обновлений и драйверов в установщик со средой восстановления и файл ответов (см. «Файл ответов»). Драйверы и обновления класть в `Config` не обязательно: пункты со стрелкой в сводке открывают окно выбора папки (например, «Загрузки» или флешка с драйверами производителя), а пункт «Взять драйверы с этого компьютера» выгружает драйверы текущей Windows. После этого сводка показывается снова, остальной выбор в ней сохраняется. В окне те же настройки собраны в разделе «Дополнительно», а папку с обновлениями или драйверами выбирает кнопка «Другая папка…».

Чтобы держать несколько наборов настроек, скопируйте папку (например, в `Config-Office`) и запускайте с `-ConfigPath .\Config-Office`.

## Быстрый старт

Проще всего одной командой. Откройте PowerShell и выполните:

```powershell
irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1 | iex
```

Команда скачает последний релиз в папку `LunqDebloater` вашего профиля (`C:\Users\<имя>\LunqDebloater`) и запустит скрипт в пошаговом режиме, дальше пункты 3-5. Подробнее в разделе «Запуск одной командой».

Если удобнее окно, скачайте из [последнего релиза](https://github.com/Lunqasd1337/LunqDebloater/releases/latest) один `LunqDebloater.exe` и запустите: остальное он скачает сам (см. «Окно»). Команда выше тоже кладёт `LunqDebloater.exe` в папку программы.

Или вручную:

1. Скачайте репозиторий (Code → Download ZIP) и распакуйте его.
2. Дважды щёлкните `Start.cmd`. Скрипт попросит права администратора.
3. Дальше он всё спросит сам: выберите, собрать ISO или посмотреть, что в образе, затем ISO в окне выбора файла, затем категории твиков, проверьте сводку «Что войдёт в образ» и выберите редакцию (у каждой редакции есть короткое пояснение).
4. Проверьте план сборки и подтвердите. Сборка обычно занимает 15-40 минут, в консоли видно «Шаг N из M» с пояснением, что происходит.
5. В конце скрипт покажет итог: что удалено, чего не нашлось в образе, где лежит готовый ISO.

## Окно

`LunqDebloater.exe` собирает ISO без консоли. Это оболочка над тем же скриптом: окно запускает `LunqDebloater.ps1` с параметрами и показывает, что он сообщает, поэтому проверки, сборка и лог те же, что в консоли.

1. Скачайте `LunqDebloater.exe` из [последнего релиза](https://github.com/Lunqasd1337/LunqDebloater/releases/latest) и запустите его, например прямо из «Загрузок». Окно сразу попросит права администратора: без них скрипт не подключит ISO.
2. При первом запуске рядом с exe нет `LunqDebloater.ps1`, и окно предложит скачать LunqDebloater в `C:\Users\<имя>\LunqDebloater` (кнопка «Другая папка…» меняет папку). Оно ставит его тем же загрузчиком `Install.ps1`, что и запуск одной командой, кладёт туда `LunqDebloater.exe` и открывается уже оттуда. Дальше запускайте exe из этой папки. Exe в «Загрузках» тоже работает: он сразу открывает установленный, а если сам новее, предлагает обновить папку. Ваши изменения в `Config` при обновлении остаются.
3. **Образ Windows.** Нажмите «Выбрать ISO…». Окно прочитает список редакций и заранее выберет Pro, если она есть. Перетащить ISO в окно нельзя: Windows не пускает перетаскивание из обычных окон в окна с правами администратора.
4. **Что убрать и отключить.** Категории профиля `Config\Profile.json` с описаниями. Включённые в профиле уже отмечены.
5. **Готовый образ.** Куда сохранить ISO (по умолчанию рядом с исходным) и файл ответов: установка без лишних вопросов, вход без учётной записи Майкрософт, обход проверки TPM 2.0 и Secure Boot (см. «Файл ответов»).
6. Нажмите «Собрать ISO». Если такой файл уже есть, окно спросит, заменить ли его.

В разделе «Дополнительно» лежат обновления и драйверы (из `Config\Updates` и `Config\Drivers` или из другой папки), очистка хранилища компонентов, обновление установщика и WinRE, драйверы дисков для установщика, программы и скрипты первого входа, метка тома и рабочая папка.

Во время сборки видны «Шаг N из M», полоса, пройденные шаги со временем и число предупреждений, а кнопка «Открыть лог» открывает лог запуска. В конце окно показывает, где лежит ISO (кнопка «Показать в папке»), что сделано по шагам и все предупреждения. Если сборка остановилась, видны причина, проверки, которые не прошли, с подсказками и кнопка «Отчёт об ошибке» с архивом для issue. Если закрыть окно во время сборки, скрипт доработает в фоне, а итог будет в его логе.

Чего в окне нет, для этого остаётся консоль: режима «Что в образе», выбора одного из нескольких профилей (окно всегда берёт `Config\Profile.json`), выгрузки драйверов этого компьютера и редких параметров вроде `-ConfigPath`, `-SkipAppx` или `-SkipVersionCheck`. Язык окна переключается кнопками RU и EN вверху. Окну нужен WebView2, в Windows 11 он уже есть.

## Запуск одной командой

`irm ... | iex` скачивает и выполняет [Install.ps1](Install.ps1). Его можно прочитать до запуска. Загрузчик делает вот что:

- узнаёт на GitHub последний релиз (не текущий `main`) и раскладывает его в `C:\Users\<имя>\LunqDebloater`. Папка в профиле выбрана потому, что скрипт работает из неё с правами администратора, а файлы в корне диска C: могут менять и другие пользователи компьютера;
- кладёт рядом окно `LunqDebloater.exe` из того же релиза. Если к релизу его ещё не приложили (это делает GitHub Actions через несколько минут после выпуска), загрузчик предупредит и докачает окно при следующем запуске;
- запускает `LunqDebloater.ps1` в Windows PowerShell 5.1, даже если команду ввели в PowerShell 7. Права администратора скрипт попросит сам.

Та же команда обновляет программу вместе с окном. Если версия уже последняя, скрипт сразу запускается. При обновлении папки программы заменяются целиком. Файлы в `Config`, которые вы изменили, остаются, и загрузчик их перечислит. Ваши файлы рядом (ISO, `Logs`) не трогаются. Без интернета запускается уже скачанная версия.

Другая папка задаётся так:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1))) -Path D:\LunqDebloater
```

В непустую папку, где нет LunqDebloater, загрузчик ничего не кладёт. Менять файлы в папке программы могут только вы, администраторы и SYSTEM: загрузчик сам ставит такие права, поэтому папка в корне диска тоже безопасна. На флешке с FAT32 или exFAT прав доступа нет, и загрузчик об этом предупредит.

### Ярлык на рабочем столе

Ярлык с этой командой при каждом запуске проверяет обновления и запускает последнюю версию. Щёлкните правой кнопкой по рабочему столу, выберите «Создать» → «Ярлык» и вставьте в поле «Укажите расположение объекта»:

```text
powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1 | iex"
```

Назовите ярлык, например, «LunqDebloater». Окно консоли не закроется само: в конце скрипт ждёт Enter.

## Запуск с параметрами

Все параметры описаны в таблице ниже. `Get-Help .\LunqDebloater.ps1` показывает их список и ссылки на это описание, а `Get-Help .\LunqDebloater.ps1 -Online` открывает его на GitHub. Для повторных сборок и автоматизации всё можно задать параметрами, тогда скрипт ничего не спрашивает и берёт всё, что есть в `Config`:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
Get-ChildItem -Recurse | Unblock-File   # если архив скачан из интернета

.\LunqDebloater.ps1 -IsoPath D:\Win11_26H2.iso -Edition "Windows 11 Pro"
```

Если не указать `-Edition` или `-Index`, скрипт покажет список редакций и спросит номер. Без `-IsoPath` он работает в пошаговом режиме, как через `Start.cmd`. Итоговый ISO по умолчанию появится рядом с исходным (`Win11_26H2_Lunq.iso`), лог запуска будет в папке `Logs` рядом со скриптом (см. «Логи и версия»).

| Параметр | Назначение |
|---|---|
| `-IsoPath` | Исходный ISO. Без него включается пошаговый режим |
| `-OutputIso` | Путь к итоговому ISO |
| `-ConfigPath` | Папка с настройками вместо `Config` рядом со скриптом |
| `-ProfilePath` | Свой JSON-профиль вместо `Config\Profile.json` |
| `-SkipCategory` | Id категорий профиля, которые нужно пропустить, через запятую |
| `-IncludeCategory` | Id категорий, которые нужно включить, даже если в профиле они выключены (например, `drivers`), через запятую |
| `-Index` / `-Edition` | Редакция по номеру или имени |
| `-WorkDir` | Рабочая папка. Скрипт очищает её целиком, поэтому подойдёт только новая или пустая папка (или созданная им раньше), но не корень диска и не папка с ISO. Доступ к ней есть только у администраторов |
| `-OscdimgPath` | Путь к `oscdimg.exe` или к папке с ним, если ADK стоит не в стандартной папке |
| `-UpdatesPath` | Папка с обновлениями `.msu`/`.cab` вместо `Config\Updates` (подпапки `SafeOS` и `Setup` ищутся в ней же) |
| `-DriversPath` | Папка с драйверами (`.inf`, можно в подпапках) вместо `Config\Drivers` |
| `-DriversToSetup` | Добавить драйверы контроллеров дисков ещё и в установщик (`boot.wim`) и среду восстановления (WinRE), если они не видят диск |
| `-UpdatesToSetup` | Встроить обновления Windows ещё и в установщик и WinRE, а также Safe OS и Setup Dynamic Update (из подпапок `SafeOS` и `Setup` или распознанные в самой папке) |
| `-SkipUpdates`, `-SkipDrivers` | Не встраивать обновления или драйверы из `Config` |
| `-SkipApps`, `-SkipScripts` | Не ставить программы из `Apps.txt` или не выполнять скрипты из `Scripts` при первом входе |
| `-Unattend` | Положить в ISO файл ответов: без вопросов о лицензии и конфиденциальности, язык, регион и часовой пояс как на этом компьютере |
| `-BypassRequirements` | Добавить в файл ответов обход требований TPM 2.0, Secure Boot и памяти (включает `-Unattend`) |
| `-LocalAccount` | Добавить в файл ответов вход без учётной записи Майкрософт (включает `-Unattend`) |
| `-ListContents` | Не собирать ISO, а сохранить список приложений и компонентов редакции в файл |
| `-SkipAppx`, `-SkipComponents`, `-SkipRegistry` | Пропустить шаг |
| `-Label` | Метка тома итогового ISO: латинские буквы, цифры, `_` и `-`, до 32 символов. По умолчанию `LUNQ_WIN11` |
| `-SkipVersionCheck` | Не останавливаться, если сборка ISO не совпадает с `Requirements` профиля |
| `-CleanupComponents` | Очистить хранилище компонентов (`/ResetBase`): образ меньше, но обновления из него нельзя удалить |
| `-KeepWorkDir` | Не удалять рабочую папку после сборки |
| `-Force` | Перезаписать существующий итоговый ISO |
| `-Language` | Язык интерфейса: `ru` или `en`. По умолчанию русский на русской Windows и английский на любой другой |
| `-EventsPath` | Файл, в который скрипт пишет события для своих программ, например окна с полосой прогресса (см. «События для своих программ»). Работает только вместе с `-IsoPath` |
| `-ListEditions` | Только показать редакции в ISO из `-IsoPath` (номер и имя) и выйти. Ничего не проверяет и не меняет. С `-EventsPath` список приходит событием `editions` |

## Как устроен процесс

1. ISO монтируется, его содержимое копируется в рабочую папку.
2. Выбранная редакция экспортируется в отдельный `install.wim` (ESD при этом конвертируется в WIM).
3. `install.wim` монтируется, в него встраиваются обновления и драйверы (если выбраны), при желании обновляется WinRE и добавляется скрипт первого входа. В корень ISO кладётся файл ответов, если он включён. Затем применяется профиль: Appx, компоненты, реестр.
4. Образ сохраняется. Если выбрано, обновляется установщик: в `sources` распаковывается Setup Dynamic Update, обслуживается `boot.wim`, и из него копируются `setup.exe`, `setuphost.exe` и загрузчик UEFI. Если для `boot.wim` нет ни обновлений, ни драйверов, он не трогается. Затем `install.wim` пересжимается, и `oscdimg` собирает загрузочный ISO.

Все шаги по порядку и условия, при которых они выполняются, описаны в [ARCHITECTURE.md](ARCHITECTURE.md#шаги-сборки).

При ошибке образ отключается без сохранения, а кусты реестра выгружаются.

## Логи и версия

Каждый запуск пишет лог в папку `Logs` рядом со скриптом, с самого старта: в него попадают и ошибки при выборе ISO, профиля и проверке системы. В первых строках лога указаны версия LunqDebloater, версия Windows и PowerShell и параметры запуска. Рядом лежит подробный лог DISM: если DISM выдал ошибку, настоящая причина обычно видна только в нём. Со встраиванием обновлений он вырастает до сотен мегабайт, поэтому в конце запуска сжимается в `LunqDebloater_<дата>_dism.zip` (открывается двойным щелчком). Хранятся логи последних 10 запусков и логи DISM последних 3, более старые удаляются сами. Путь к логу показывается в плане сборки, в итоге и при ошибке, а в окне `LunqDebloater.exe` лог открывает кнопка «Открыть лог».

У заголовка каждого шага стоит время его начала, а итог показывает три самых долгих шага. В логе DISM перед каждым шагом есть метка `===== LunqDebloater <время>: step N/M: <шаг> =====`, по ней удобно искать нужное место. Если внешняя программа (например, robocopy или oscdimg) завершилась с ошибкой, в лог попадают последние строки её вывода. При ошибке под её текстом видно, где именно она произошла.

Если сборка прервалась ошибкой, рядом с логом появляется архив `LunqDebloater_<дата>_report.zip` с логом запуска, логом DISM и профилем. Путь к папке пользователя, имя пользователя и имя компьютера в нём заменены, так что для отчёта достаточно приложить этот архив. Лог DISM больше 20 МБ в нём сокращён: все ошибки, предупреждения и метки шагов и последние 20 000 строк. Если архива нет, пришлите оба файла последнего запуска: `LunqDebloater_<дата>.log` и `LunqDebloater_<дата>_dism.zip`.

Версия LunqDebloater видна в заголовке окна консоли, рядом с названием в окне `LunqDebloater.exe`, в начале лога и в итоге сборки. Она же записывается в собранный образ вместе с настройками сборки. На установленной системе их можно посмотреть так:

```powershell
reg query HKLM\SOFTWARE\LunqDebloater
```

Там указаны версия и дата сборки, исходный ISO и редакция, файл ответов, профиль, включённые и пропущенные категории, встроенные обновления (в том числе Safe OS и Setup Dynamic Update), число драйверов, обновлялись ли установщик и WinRE, очистка хранилища, пропущенные шаги, программы и скрипты после установки. Если после установки что-то работает не так, по этим данным видно, чем и с какими настройками собран образ.

## Обновления

1. Скачайте накопительное обновление для своей версии из [каталога Центра обновления Майкрософт](https://www.catalog.update.microsoft.com), например по запросу `Windows 11 Version 26H2 x64`. Если в каталоге для него несколько файлов, скачайте все.
2. В пошаговом режиме выберите папку с ними в сводке пунктом «Выбрать папку с обновлениями», например «Загрузки». Или положите файлы в `Config\Updates`: тогда они сразу появятся в сводке, а с параметрами встроятся сами (если не нужно, добавьте `-SkipUpdates`). Другую папку с параметрами задаёт `-UpdatesPath`, а в окне кнопка «Другая папка…» под пунктом «Встроить обновления» в разделе «Дополнительно».

Обновления Safe OS и Setup Dynamic Update каталог показывает в том же поиске, что и накопительное, но они для среды восстановления и установщика, в саму систему не встанут. В `Config\Updates` для них есть подпапки:

- `Config\Updates\SafeOS`: Safe OS Dynamic Update (`.cab`), ставится в WinRE после накопительного обновления;
- `Config\Updates\Setup`: Setup Dynamic Update (`.cab`), распаковывается в `sources` ISO и обновляет файлы установщика.

В папке, выбранной в сводке или через `-UpdatesPath`, ищутся такие же подпапки. Если их нет, например в «Загрузках», Dynamic Update можно оставить рядом с остальными обновлениями: скрипт узнаёт их по содержимому `.cab`. В Setup Dynamic Update нет пакета DISM (файла `.mum`), а Safe OS Dynamic Update называется `Package_for_SafeOSDU`. Сводка помечает такие файлы. Они встраиваются только вместе с обновлением установщика и WinRE (см. «Установщик и среда восстановления»). Берите их для той же версии Windows, что и накопительное обновление.

Обновления ставятся сразу после монтирования образа, до удаления приложений и компонентов. Порядок как у Microsoft: сначала пакеты без номера KB (языковые пакеты и компоненты по запросу), затем обновления Windows по возрастанию номера KB, последними обновления .NET (`ndp` в имени). Накопительное обновление ставится долго (10-30 минут) и требует дополнительного места. После обновлений имеет смысл включить `-CleanupComponents` (в сводке и в окне это пункт под обновлениями): старые версии системных файлов удалятся, и образ станет меньше.

## Драйверы

1. Если ISO собирается для этого же компьютера, выберите в сводке пункт «Взять драйверы с этого компьютера»: скрипт выгрузит сторонние драйверы текущей Windows. Для другого компьютера выберите пунктом «Выбрать папку с драйверами» папку с распакованными драйверами (файлы `.inf` вместе с `.sys`, `.cat` и остальными, подпапки любые), например флешку с драйверами производителя. Можно и положить их в `Config\Drivers`, а с параметрами указать папку через `-DriversPath`. Как распаковать драйверы, описано в [Config/README.txt](Config/README.txt). В окне папку выбирает кнопка «Другая папка…» под пунктом «Встроить драйверы». Выгружать драйверы этого компьютера окно не умеет: выгрузите их командой из [Config/README.txt](Config/README.txt) в `Config\Drivers` или воспользуйтесь сводкой в консоли.
2. Драйверы появятся в сводке перед сборкой, а с параметрами встроятся сами (если не нужно, добавьте `-SkipDrivers`).
3. Если установщик не видит диск (контроллеры Intel RST/VMD, RAID), добавьте драйверы и в него: в сводке и в окне это пункт под драйверами, с параметрами нужен ключ `-DriversToSetup`. Тогда драйверы попадут и в среду восстановления (WinRE), и она тоже увидит диск. Туда добавляются только драйверы контроллеров дисков (класс `SCSIAdapter` или `HDC` в `.inf`): установщик при загрузке целиком распаковывается в память, и все драйверы сразу сильно замедлили бы её.

Драйверы попадают в хранилище драйверов образа, и Windows сама ставит подходящие во время установки. Каждый `.inf` добавляется отдельно, поэтому неподходящий драйвер не срывает сборку, а попадает в итог как ошибка. Драйвер в виде `.exe` без `.inf` встроить нельзя, его сначала нужно распаковать.

Это хорошо сочетается с категорией `drivers` профиля (по умолчанию выключена): она запрещает Windows Update ставить свои драйверы, а нужные вы встраиваете сами.

## Установщик и среда восстановления

Кроме самой системы в ISO есть ещё два образа на базе Windows PE:

- **установщик** (`sources\boot.wim`, образ 2), с которого загружается флешка;
- **среда восстановления** (WinRE, `Windows\System32\Recovery\Winre.wim` внутри системы), которая открывается при сбое загрузки и через «Параметры → Восстановление».

По умолчанию они остаются такими, как в ISO. С `-UpdatesToSetup` в них встраиваются те же обновления Windows, что и в систему, а с `-DriversToSetup` драйверы контроллеров дисков. В сводке перед сборкой и в разделе «Дополнительно» окна это пункты под обновлениями и драйверами. Если нашлись Safe OS или Setup Dynamic Update, в сводке пункт обновления установщика включён сразу. С `-UpdatesToSetup` в WinRE ставится и Safe OS Dynamic Update, а в `sources` ISO распаковывается Setup Dynamic Update. После обновления установщика `setup.exe` и `setuphost.exe` из `boot.wim` копируются в `sources` ISO: по инструкции Microsoft они должны совпадать с файлами в `boot.wim`, иначе установка может не запуститься. Оттуда же берётся загрузчик UEFI на ISO (`efi\boot\bootx64.efi` и `bootmgr.efi`). Обновления .NET и прочие пакеты, которые не ставятся в Windows PE, пропускаются. После обновлений оба образа очищаются от старых файлов и пересжимаются. Сборка с обновлениями займёт на 10-20 минут дольше.

## После установки

Можно сделать так, чтобы при первом входе в установленную Windows поставились нужные программы и выполнились ваши скрипты:

1. В `Config\Apps.txt` уже есть готовый список: 7-Zip, DirectX и все версии Visual C++ Redistributable, которые нужны играм и многим программам. Добавьте свои программы (Id из winget, по одному в строке) или закомментируйте ненужные через `#`. В конце файла есть ещё примеры.
2. Если нужно, положите в `Config\Scripts` свои скрипты `*.ps1`. Они выполнятся после программ, по порядку имён, с правами администратора. Остальные файлы из этой папки тоже копируются, и скрипты могут ими пользоваться.
3. Программы и скрипты появятся в сводке перед сборкой и в разделе «Дополнительно» окна, а с параметрами добавятся сами (если не нужно, добавьте `-SkipApps` или `-SkipScripts`).

При первом входе откроется окно с ходом работы. Скрипт дождётся интернета и winget, тихо поставит программы, выполнит скрипты и закроет окно. Если интернета нет, программа не поставилась или окно закрыли на середине, недоделанное повторится при следующем входе (до 5 попыток). Пока программы не поставились, скрипты ждут: они выполнятся после программ или на последней попытке. Скрипт с ошибкой повторно не запускается. Ваши скрипты и лог доступны только администраторам, а если поставить такие права не удалось, это написано в логе. В самом ISO и на флешке они лежат открыто внутри `install.wim`: кто получит ISO, сможет их прочитать, поэтому не отдавайте другим ISO с паролями в скриптах. Когда всё сделано, копии ваших скриптов и всё, что лежало рядом с ними, удаляются с диска: там могут быть пароли и ключи. Остаются только `Apps.txt` и лог `C:\Windows\Setup\Scripts\Lunq\FirstLogon.log`. Подробности в [Config/README.txt](Config/README.txt).

Скрипты можно сохранять в любом редакторе. Windows PowerShell 5.1 читает файл в UTF-8 без метки BOM как ANSI, и русский текст в кавычках ломает весь скрипт. Поэтому при сборке такие файлы пересохраняются в UTF-8 с BOM, это видно в выводе шага.

Скрипт считается неудачным, если он выбросил ошибку или завершился с кодом выхода не 0. Код выхода берётся и от последней внешней программы в скрипте: например, robocopy возвращает 1 и при успехе. Если так и задумано, допишите в конце скрипта `exit 0`.

Если записываете флешку через Rufus, не отмечайте в его окне ни одну настройку Windows, в том числе обход требований TPM, Secure Boot и памяти. Для них Rufus добавляет свой файл ответов, Windows берёт его вместо файла LunqDebloater, и программы со скриптами после установки сами не запустятся. Обход требований и локальную учётную запись лучше включить в файле ответов LunqDebloater (см. «Файл ответов»). Если без настроек Rufus или своего `autounattend.xml` всё же не обойтись, после установки запустите всё вручную из PowerShell от имени администратора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Windows\Setup\Scripts\Lunq\FirstLogon.ps1
```

## Файл ответов

Файл ответов (`autounattend.xml` в корне ISO) отвечает за человека на часть вопросов установки Windows. Windows Setup находит его на флешке сама. В пошаговом режиме он включён по умолчанию (пункты под «Файл ответов» в сводке), с параметрами включается ключом `-Unattend`. В окне он тоже включён по умолчанию: переключатель «Установка без лишних вопросов» в разделе «Готовый образ» отвечает за оба первых пункта таблицы, а переключатели под ним за `-LocalAccount` и `-BypassRequirements`.

| Пункт сводки | Ключ | Что делает |
|---|---|---|
| Не спрашивать про лицензию и конфиденциальность | `-Unattend` | Лицензия принимается сама, все параметры конфиденциальности (диагностика, реклама, местоположение) выключены, страница с ними не показывается |
| Язык, регион и часовой пояс как на этом компьютере | `-Unattend` | Язык установщика и Windows берётся из образа, а формат, раскладки клавиатуры и часовой пояс с компьютера, на котором собирается ISO |
| Обойти требования Windows 11 | `-BypassRequirements` | Установка не проверяет TPM 2.0, Secure Boot и объём памяти. Для компьютеров, на которые Windows 11 иначе не ставится |
| Локальная учётная запись | `-LocalAccount` | Windows не предлагает войти в учётную запись Майкрософт и сразу спрашивает имя и пароль локальной |

Диск для установки, ключ продукта (можно нажать «У меня нет ключа») и сеть по-прежнему выбираются вручную: файл ответов ничего не стирает сам. Пароли в нём не хранятся, имя и пароль учётной записи вводятся при установке. Если в образе есть программы или скрипты после установки, их команда тоже записывается в этот файл.

С Rufus не отмечайте настройки Windows в его окне: он добавит свой файл ответов вместо этого. Работу файла ответов на настоящей установке стоит проверить в виртуальной машине: сборка проверялась только на заглушках.

## Что в образе

Чтобы составить свой профиль, полезно знать точные имена приложений и компонентов в своей редакции. В пошаговом режиме выберите в начале «Посмотреть, что есть в образе», а с параметрами добавьте `-ListContents`:

```powershell
.\LunqDebloater.ps1 -IsoPath D:\Win11.iso -Edition "Windows 11 Pro" -ListContents
```

Скрипт ничего не собирает и не меняет. Он копирует редакцию в рабочую папку, открывает её только для чтения и сохраняет рядом с ISO файл `<имя ISO>_<номер редакции>_contents.txt`. В файле перечислены приложения Appx, установленные компоненты (Capabilities) и функции Windows (включённые и выключенные). Справа у каждого элемента указаны категории профиля, которые его уже удаляют. В конце файла собраны записи профиля, которых нет в образе. Для этого режима Windows ADK не нужен. В окне `LunqDebloater.exe` этого режима нет.

## События для своих программ

Чтобы запускать сборку из своей программы (например, окна с полосой прогресса), передайте `-EventsPath` с путём к файлу. Скрипт работает как обычно, лог и вывод в консоль не меняются, но всё, что он сообщает, ещё и пишется в этот файл событиями: одна строка это один объект JSON в UTF-8. Строки дописываются сразу, а файл можно читать, пока идёт сборка. С `-EventsPath` скрипт ничего не спрашивает, поэтому нужны `-IsoPath` и, если в ISO больше одной редакции, `-Index` или `-Edition`.

```powershell
.\LunqDebloater.ps1 -IsoPath D:\Win11.iso -Edition "Windows 11 Pro" -Force -EventsPath C:\Temp\lunq.jsonl
```

```
{"type":"start","time":"2026-10-17T19:02:11.5+03:00","language":"ru","mode":"build","pid":4120,"version":"1.10.0"}
{"type":"step","time":"...","hint":null,"id":"Updates","index":5,"text":"Встраивание обновлений","total":17}
{"type":"info","time":"...","text":"windows11.0-kb2-x64.cab не подходит к этому образу, пропускаю."}
{"type":"done","time":"...","bugReport":null,"contents":null,"dismLog":"...","iso":"D:\\Win11_Lunq.iso","log":"...","ok":true,"seconds":1834.2,"warnings":0}
```

У каждого события есть `type` и `time`. Остальные поля:

| `type` | Когда | Поля |
|---|---|---|
| `start` | Сразу после запуска | `version`, `language`, `mode` (`build`, `list` или `editions`), `pid` |
| `log` | Лог начат | `path`, `dismLog` |
| `section` | Новый раздел вывода | `text` |
| `editions` | Прочитан список редакций ISO | `items`: `index` и `name` каждой |
| `step` | Начался шаг сборки | `index`, `total`, `id` (имя шага, одно на всех языках), `text`, `hint` |
| `stepEnd` | Шаг закончился | `index`, `id`, `ok`, `seconds` |
| `check` | Строка проверки | `status` (`ok`, `warn`, `fail`), `text`, `hint` |
| `info` | Обычная строка вывода | `text` |
| `warning` | Предупреждение | `text` |
| `result` | Итог шага после сборки | `kind`, `title`, `done`, `failed`, `skipped`, `notMatched`, `summary` |
| `error` | Сборка прервалась ошибкой | `text`, `where` (где она произошла) |
| `done` | Последнее событие запуска | `ok`, `iso`, `contents` (файл режима `-ListContents`), `log`, `dismLog`, `bugReport`, `warnings`, `seconds` |

Тексты в событиях на языке интерфейса, его задаёт `-Language`. Последнее событие всегда `done`, а код выхода `powershell.exe` при ошибке не равен 0. Скрипту нужны права администратора, поэтому программа запускает его с ними сама, например через `Start-Process -Verb RunAs`, и читает файл событий, а не вывод процесса: вывод процесса с другими правами недоступен.

Так устроено окно `LunqDebloater.exe` (папка `Gui`): оно само запускается с правами администратора, запускает скрипт с `-EventsPath`, читает файл и рисует шаги и итог. Его код можно взять за пример, а список редакций для выбора оно получает запуском с `-ListEditions`.

## Профиль

Всё, что удаляется и меняется, описано в `Config\Profile.json`. Правьте его под себя или положите рядом ещё профили (`*.json`): тогда скрипт спросит, какой взять (окно всегда берёт `Profile.json`). Профиль состоит из категорий: в каждой собрано всё, что относится к одной теме (приложения, компоненты, функции и реестр), и её можно целиком включить или выключить.

```jsonc
{
  "$schema": "../Schemas/Profile.schema.json",   // подсказки и проверка в VS Code
  "Name": "Default",
  "Description": "Что делает профиль",
  "Options": { "RemoveFeaturePayload": false },   // удалять ли файлы отключённых функций
  "Categories": [
    {
      "Id": "ai",                                 // короткое имя для -SkipCategory и -IncludeCategory
      "Name": { "ru": "Copilot и ИИ", "en": "Copilot and AI" },
      "Enabled": true,                            // false: категория пропускается
      "Description": "Что делает категория",
      "Appx":         ["Microsoft.Copilot"],      // DisplayName, можно с *
      "Capabilities": [],                         // Get-WindowsCapability, можно с *
      "Features":     ["Recall"],                 // Get-WindowsOptionalFeature
      "Packages":     [],                         // CBS-пакеты, осторожно
      "Registry": [
        { "Hive": "SOFTWARE", "Path": "Policies\\Microsoft\\Windows\\WindowsCopilot", "Name": "TurnOffWindowsCopilot", "Type": "REG_DWORD", "Value": 1 },
        { "Hive": "DefaultUser", "Path": "Software\\Microsoft\\Windows\\CurrentVersion\\Run", "Name": "OneDriveSetup", "Action": "DeleteValue" },
        { "Hive": "SOFTWARE", "Path": "Microsoft\\WindowsUpdate\\Orchestrator\\UScheduler_Oobe\\OutlookUpdate", "Action": "DeleteKey" }
      ]
    }
  ]
}
```

Пустые списки в категории можно не писать.

Тексты `Name` и `Description` (у профиля, категорий и записей реестра) можно писать строкой или переводами: `{ "ru": "...", "en": "..." }`. Скрипт берёт язык интерфейса, затем английский. Строка `"$schema"` подключает схему [Schemas/Profile.schema.json](Schemas/Profile.schema.json): по ней VS Code подсказывает поля и подчёркивает ошибки.

### Требования к версии Windows

Профиль может указать, на какую сборку Windows он рассчитан:

```json
"Requirements": { "Build": 26300, "MinRevision": 9457, "Architecture": "amd64" }
```

- `Build`: номер сборки должен совпадать точно (26300 соответствует 26H2, 26200 соответствует 25H2, 26100 соответствует 24H2).
- `MinRevision`: минимальная ревизия, то есть число после точки в `26300.9457`. Всё, что новее, подходит, так что профиль не нужно править после каждого ежемесячного обновления.
- `Architecture`: `amd64` или `arm64`.

Скрипт сверяет это с выбранной редакцией сразу после чтения ISO, ещё до копирования файлов. Если сборка не подходит, он останавливается и подсказывает, где скачать свежий ISO. Если не хватает только ревизии, а в папке обновлений есть накопительное обновление Windows, скрипт лишь предупреждает: обновление поднимет ревизию. Чтобы собрать образ на другой сборке сознательно, запустите скрипт с `-SkipVersionCheck`. Если блока `Requirements` в профиле нет, проверка не выполняется. Профиль старого формата (с `Appx`, `Registry` и т.д. на верхнем уровне, без `Categories`) тоже работает: он считается одной категорией.

Категории в `Profile.json`:

| Id | Категория |
|---|---|
| `apps` | Встроенные приложения |
| `legacy` | Устаревшие компоненты |
| `telemetry` | Телеметрия и диагностика |
| `ai` | Copilot и ИИ |
| `ads` | Реклама и предложения |
| `search` | Поиск и Bing |
| `store` | Microsoft Store |
| `drivers` | Драйверы из Windows Update |
| `onedrive` | OneDrive |

Пропустить категории без правки профиля: `-SkipCategory store,onedrive`, а включить выключенную: `-IncludeCategory drivers`. В пошаговом режиме скрипт показывает список категорий, и их можно включать и выключать по номерам, а в окне это переключатели в разделе «Что убрать и отключить».

Записи реестра:

- `Hive`: `SOFTWARE` (HKLM\SOFTWARE), `SYSTEM` (HKLM\SYSTEM, используйте `ControlSet001` вместо `CurrentControlSet`) или `DefaultUser` (HKCU для всех новых пользователей).
- `Name`: имя значения. Если не указать, запись относится к значению «по умолчанию» у ключа.
- `Action`: `Set` (по умолчанию), `DeleteValue` или `DeleteKey`.
- `Type`: `REG_DWORD`, `REG_QWORD` (число или строка `"0x..."`), `REG_SZ`, `REG_EXPAND_SZ`, `REG_MULTI_SZ` (массив строк), `REG_BINARY` (hex-строка, например `"de ad be ef"`).
- `Value`: значение. Строки записываются как есть, с кавычками и `\` в конце.
- `Description`: пояснение, необязательно. Скрипт и окно его не показывают, оно для людей, которые читают профиль.

Ошибку в записи (неизвестный тип или действие, не число в `REG_DWORD`) скрипт покажет сразу при чтении профиля, ещё до сборки.

Узнать точные имена в своём образе проще всего режимом «Что в образе» (см. выше). Вручную это можно сделать так (после `Mount-WindowsImage`):

```powershell
Get-AppxProvisionedPackage -Path C:\LunqWork\mount | Select DisplayName
Get-WindowsCapability     -Path C:\LunqWork\mount | Where State -eq Installed | Select Name
Get-WindowsOptionalFeature -Path C:\LunqWork\mount | Where State -eq Enabled | Select FeatureName
```

Категория `drivers` отключает загрузку драйверов из Windows Update и по умолчанию выключена. Если в системе нет встроенного драйвера сетевой карты или Wi-Fi, после установки не будет интернета, и драйвер придётся ставить вручную. Включайте её (`"Enabled": true` в профиле, `-IncludeCategory drivers`, по номеру в пошаговом режиме или переключателем в окне), только если встраиваете нужные драйверы в образ сами (см. раздел «Драйверы»).

Профиль по умолчанию не трогает Microsoft Store, App Installer (winget), Терминал, Фотографии, Калькулятор, Блокнот и Безопасность Windows. Списки `Packages` пусты намеренно: удаление CBS-пакетов может сломать установку обновлений.

## Разработка

Код разложен так:

| Путь | Что там |
|---|---|
| `LunqDebloater.ps1` | Сам скрипт: параметры, пошаговый режим, проверки и план сборки |
| `Install.ps1` | Загрузчик для запуска одной командой (`irm ... \| iex`) |
| `Modules\LunqDebloater\` | Модуль с функциями. Версия задаётся в манифесте `LunqDebloater.psd1` |
| `Modules\LunqDebloater\Private\` | Функции по темам: `Console`, `Language`, `Profile`, `Iso`, `Checks`, `Image`, `Servicing`, `Removal`, `Registry`, `PostInstall`, `Unattend`, `Inventory`, `Options` (сводка «Что войдёт в образ»), `Build` (шаги сборки), `Report`, `System` |
| `Modules\LunqDebloater\Strings\` | Тексты интерфейса: `ru\*.psd1` и `en\*.psd1` |
| `Modules\FirstLogon\FirstLogon.ps1` | Скрипт первого входа, который кладётся в образ |
| `Schemas\Profile.schema.json` | JSON-схема профиля |
| `Gui\` | Окно на Tauri: `src-tauri` (Rust: запуск скрипта и чтение событий) и `ui` (HTML, CSS и JS без сборщика) |
| `Tests\` | Тесты Pester и заглушка модуля DISM (окно проверяет `Tests\Gui.Tests.ps1`) |

Тесты не трогают систему: вместо DISM, reg.exe, oscdimg и winget работают заглушки, а сборка идёт в папке теста. Запустить их и анализатор (нужны Pester 5 и PSScriptAnalyzer):

```powershell
Install-Module Pester -MinimumVersion 5.5.0 -MaximumVersion 5.99.99 -Scope CurrentUser -Force -SkipPublisherCheck
Install-Module PSScriptAnalyzer -MinimumVersion 1.23.0 -Scope CurrentUser -Force
Invoke-Pester -Path .\Tests
Invoke-ScriptAnalyzer -Path .\LunqDebloater.ps1 -Settings .\PSScriptAnalyzerSettings.psd1
Invoke-ScriptAnalyzer -Path .\Install.ps1 -Settings .\PSScriptAnalyzerSettings.psd1
Invoke-ScriptAnalyzer -Path .\Modules -Recurse -Settings .\PSScriptAnalyzerSettings.psd1
```

Окно собирается так (нужны [Rust](https://rustup.rs) и Visual Studio Build Tools с компонентом «Разработка классических приложений на C++»):

```powershell
cd Gui\src-tauri
cargo build --release
```

Готовый `target\release\LunqDebloater.exe` сам находит скрипт выше по папкам, поэтому его можно запускать прямо оттуда. Перед PR с изменениями окна прогоните ещё `cargo clippy -- -D warnings` в той же папке.

То же самое GitHub Actions выполняет для каждого PR, а собранное окно прикладывает к запуску как артефакт `LunqDebloater-window`. К каждому опубликованному релизу `LunqDebloater.exe` прикладывается сам (`.github\workflows\window-release.yml`). Что поменялось в каждой версии, записано в [CHANGELOG.md](CHANGELOG.md).

Подробно устройство кода, порядок шагов сборки и тесты описаны в [ARCHITECTURE.md](ARCHITECTURE.md). Как предложить изменение и сообщить об ошибке, описано в [CONTRIBUTING.md](.github/CONTRIBUTING.md), об уязвимости в [SECURITY.md](.github/SECURITY.md). Правила для ИИ-помощников (Claude Code, Codex, Copilot) лежат в [AGENTS.md](AGENTS.md). Схема профиля лежит в `Schemas\Profile.schema.json`; `.vscode\settings.json` подключает её к профилям в папках `Config*`, так что VS Code подсказывает поля профиля и проверяет их даже без интернета.
