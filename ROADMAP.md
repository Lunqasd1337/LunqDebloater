# Roadmap LunqDebloater

Дата: 7 ноября 2026 года. Статус: решения R0 частично согласованы, реализация и испытания не подтверждены. Наличие этих документов не означает готовность кода.

Архитектура и требования: [PLAN.md](PLAN.md). Правила разработки: [AGENTS.md](AGENTS.md). PLAN.md и ROADMAP.md ведутся на русском, AGENTS.md — на английском. Общение с пользователем — на русском, если он явно не попросил другой язык.

## Принципы выполнения

- Переход к выпуску определяется критериями готовности, а не календарной датой.
- Каждый этап завершается работающим сценарием и проверяемым отчётом.
- Зависимости ниже — зависимости результатов; они не требуют нескольких разработчиков или параллельных агентов.
- Сроки — предварительные диапазоны для одного опытного Windows/.NET-разработчика при доступных образах и оборудовании. После R1 оценку нужно пересмотреть. Это не обязательство по дате выпуска.
- `[ ]` означает невыполненное; `[x]` допускается только с подтверждением в отчёте/PR. Общий статус этапа обновляется отдельно.

## R0 — Решения и тестовое окружение

Подготовку окружения и проверки R0 пользователь выполняет сам. Это включает подготовку Hyper-V, проверку ISO и FoD, версий инструментов и инвентаризацию оборудования. На следующих этапах пользователь также сам проверяет образы в Hyper-V и драйверы на реальном ПК. Агент готовит шаги проверки и отмечает результаты по данным пользователя.

Зависимости: нет. Оценка: 3–5 рабочих дней.

- [x] Согласовать название LunqDebloater, публичный репозиторий https://github.com/Lunqasd1337/LunqDebloater, лицензию MIT и хост Windows 11 — подтверждено пользователем.
- [x] Согласовать целевой диапазон Windows 11 23H2+ и значение Capabilities / Features on Demand — подтверждено пользователем.
- [x] Согласовать производителей ASRock, GIGABYTE, MSI и ASUS — подтверждено пользователем.
- [x] Добавить обязательные видеодрайверы AMD/NVIDIA: автоопределение GPU, ручной выбор модели, поиск, скачивание и предложение интеграции — подтверждено пользователем.
- [x] Зафиксировать оборудование пользователя: ASRock B650 PG Lightning WiFi, NVIDIA GeForce RTX 5060 8 GB (не Ti), AMD Ryzen 7 7800X3D.
- [x] Согласовать только x64, без ARM64 и 32-битной x86; цель — все редакции Windows 11 с отдельной проверкой совместимости.
- [x] Согласовать русский/английский интерфейс и светлую/тёмную/системную темы.
- [x] Согласовать первую версию с интеграцией GPU-драйверов; дополнительные приложения NVIDIA/AMD отложить.
- [ ] Проверить ревизию платы, Hardware IDs и доступность встроенной AMD-графики; определить дополнительное оборудование для AMD-тестов. Hyper-V не заменяет проверку драйвера на физическом GPU. По сообщению владельца, встроенная AMD-графика отключена. Получены первые идентификаторы RTX 5060, Hardware ID требует сверки. Ревизия платы, идентификаторы встроенных контроллеров и физический стенд AMD ожидают подтверждения. [Результаты и инструкция](docs/r0/hardware-inventory.md)
- [ ] Проверить LICENSE, структуру репозитория и минимальные требования хоста; выбор лицензии не означает, что файл уже создан.
- [ ] Получить предложенные пользователем ISO 23H2/24H2/25H2/26H2, проверить edition/build/language, архитектуру x64 и хеши; составить матрицу всех доступных редакций и отдельно обозначить ещё не проверенные варианты.
- [ ] Выбрать порядок реализации адаптеров и 2–3 модели для первого драйверного пилота, включая ревизии.
- [ ] Проверить версии .NET, ADK/DISM, Oscdimg, updater и способ их доставки.
- [ ] Подготовить Hyper-V VM и проверить исходные образы. Найти совместимые FoD-источники и определить безопасную среду физических испытаний; рабочую ОС пользователя не переустанавливать без отдельного поручения.
- [ ] Создать ADR архитектуры, матрицу совместимости и схему хранения тестовых ресурсов вне Git.
- [ ] Описать будущую подпись каталогов/релизов и владельца обновления метаданных.

Готово, когда: утверждён ограниченный поддерживаемый набор; доступны необходимые ресурсы; список неизвестных не блокирует вертикальный прототип.

Артефакты: ADR, начальная матрица, инструкция подготовки окружения.

## R1 — Вертикальный прототип обслуживания

Зависимости: R0. Оценка: 2–3 недели.

- [ ] Создать решение, Domain/Application/Servicing/Worker и минимальный CLI.
- [ ] Получить метаданные WIM, выбрать индекс и сделать рабочую копию.
- [ ] Проверить окружение, смонтировать копию и считать Features.
- [ ] Изменить одну заранее выбранную поддерживаемую функцию.
- [ ] Выполнить повторную инвентаризацию, commit/unmount и экспорт.
- [ ] Подготовить ISO через Oscdimg и установить его в VM.
- [ ] Записать версии инструментов, команды/операции, хеши и результат установки.
- [ ] Проверить, что исходник и установленная Windows хоста не изменились.

Готово, когда: реальный цикл «исходник → изменение → новый ISO → установленная Windows» пройден в Hyper-V на выбранных конфигурациях Windows 11 из диапазона 23H2+. Один успешный mock-тест или создание файла ISO не закрывает этап.

Артефакты: прототип, отчёты VM, уточнённые риски и оценки следующих этапов.

- [ ] Реализовать темы Light/Dark/System, сохранение выбора и реакцию System на смену темы Windows; проверить читаемость таблиц, ошибок и прогресса в обеих темах.
- [ ] Поддержать импорт ISO/ESD с подготовкой рабочего WIM.

Готово, когда: проект переживает перезапуск UI; прерванное задание распознаётся и корректно восстанавливается либо предлагает пересборку; worker не принимает команды для чужих путей и сессий.

Артефакты: ранняя внутренняя alpha, схема проекта/IPC, отчёт recovery и проверок границы прав.

## R4 — REG-импорт и каталог твиков

Зависимости: R2; объединённая проверка с R3. Оценка: 2–4 недели.

- [ ] Реализовать парсер .reg с типами, удалениями, переносами строк, кодировками и диагностикой.
- [ ] Добавить drag-and-drop, предпросмотр и включение операций в план.
- [ ] Реализовать маршрутизацию SOFTWARE/SYSTEM, CurrentControlSet и контекстов HKCU/HKCR.
- [ ] Выбрать и проверить backend офлайн-реестра; гарантировать освобождение handles.
- [ ] Сохранять исходное состояние и выявлять конфликты между файлами и твиками.
- [ ] Создать небольшой каталог проверенных твиков с применимостью и источниками.
- [x] Получить пять пользовательских REG-файлов, сохранить неизменённые копии, сверить SHA-256 и просмотреть явные секреты/персональные данные. Описать операции и ограничения в [docs/registry/README.md](docs/registry/README.md).
- [ ] Подтвердить применимость пользовательских REG-примеров на выбранных Windows 11 в Hyper-V; отличать противоположные пресеты от восстановления исходного состояния. Документирование файлов не означает готовность импортёра.
- [ ] Реализовать ограниченный механизм первого входа для выбранных пользовательских настроек.
- [ ] Проверить настройки на двух новых пользователях, а не только на первом администраторе.

Готово, когда: перенос REG-файла не меняет хост; операции понятны до применения; неоднозначные ветки блокируются; поддержанные настройки подтверждены после установки и создания пользователей.

Артефакты: REG fixtures, схема твиков, отчёты офлайн- и пользовательских проверок.

- [ ] Добавить выбор stable/preview с выключенным preview по умолчанию.

Готово, когда: программа сама выбирает, скачивает и интегрирует корректный набор для заявленных конфигураций; зависимости объяснимы; неизвестные комбинации не устанавливаются автоматически; подтверждена дальнейшая обновляемость тестовых образов.

Артефакты: подписанный тестовый каталог, resolver tests, отчёты цепочек обслуживания и VM.

## R6 — Подбор драйверов по оборудованию

Зависимости: R3 и проверенный DownloadManager из R5. Исходная оценка 3–6 недель относится только к первому провайдеру плат. Общую оценку R6 пересчитать после прототипов AMD/NVIDIA и выбора тестового оборудования.

- [ ] Получать модель платы и системы через CIM, Hardware IDs через SetupAPI/Configuration Manager.
- [ ] Реализовать экспорт/импорт профиля оборудования без лишних персональных данных.
- [ ] Добавить ручной поиск производителя, модели и ревизии платы.
- [ ] Добавить определение всех GPU через аппаратные ID, включая встроенную/дискретную графику и общий адаптер без установленного драйвера.
- [ ] Добавить ручной ввод GPU с выбором точной модели AMD/NVIDIA и Desktop/Notebook; поддержать профиль другого ПК.
- [ ] Реализовать AmdGraphicsProvider и NvidiaGraphicsProvider: официальные источники, подбор для целевого образа, ветки драйверов и legacy/OEM-ограничения.
- [ ] Показывать кандидатов с версией, размером, источником, совместимостью и основанием выбора; скачивать и включать в план только выбранные пакеты.
- [ ] Проверить извлечение GPU-пакетов, подписи, связанные INF и устранение дублей без установки на хост. Отделить драйверы от NVIDIA App, панелей управления и AMD Software.
- [ ] Интегрировать GPU-драйверы в выбранный install.wim; не добавлять их в boot.wim/WinRE без отдельного проверенного сценария.
- [ ] Реализовать интерфейс провайдера и один реальный адаптер официального источника.
- [ ] Запланировать и проверить отдельные адаптеры остальных согласованных производителей: ASRock, GIGABYTE, MSI, ASUS. Один готовый провайдер не означает поддержку всех четырёх; оценки 3–6 недель относятся только к первому.
- [ ] Поддержать безопасное извлечение и анализ INF/CAT, ограничений ОС и архитектуры.
- [ ] Показывать основание соответствия и отделять точное совпадение от кандидата модели.
- [ ] Учесть boot-critical драйверы в подходящих install/boot/recovery-целях.
- [ ] Отдельно отображать DCH-зависимости и приложения, которые не устанавливаются через DISM.
- [ ] Проверить неизвестную ревизию, пустой SMBIOS, неподдержанную ОС и недоступность источника.
- [ ] Установить собранные образы на выбранные реальные ПК и проверить устройства.

Готово, когда: пользователь может получить профиль своего ПК или выбрать другую плату/GPU, найти кандидатов, скачать выбранный пакет и интегрировать его. Работают первый провайдер плат и оба GPU-провайдера AMD/NVIDIA на заявленном наборе моделей. Установка и работа драйверов подтверждены на физическом пилотном оборудовании; непроверенные комбинации явно помечены. Проверка только в Hyper-V не закрывает критерий видеодрайверов.

Артефакты: первый провайдер плат, провайдеры AMD/NVIDIA, hardware fixtures без идентифицирующих данных, тесты подбора/извлечения и отчёты реального оборудования.

| Функциональное покрытие запроса | R0–R7 | Есть автозагрузка обновлений, первый провайдер плат, оба GPU-провайдера AMD/NVIDIA и updater |
| Стабильный выпуск | R0–R8 | Пройдена опубликованная матрица и проверки восстановления |

Локальный MVP ещё не закрывает исходный запрос целиком: автоматические обновления, поиск драйверов и обновление программы обязательны для функционального покрытия.

## Сопровождение после выпуска

- На каждый поддерживаемый цикл обновлений Windows: обновить кандидатов каталога, проверить цепочки, провести испытания и только затем подписать метаданные.
- При изменении сайта/каталога производителя: временно пометить недоступный провайдер и сохранить ручной импорт, не подставлять непроверенные зеркала.
- Новую сборку Windows добавлять после испытаний; прекращение поддержки отображать в UI и release notes.
- Сохранять прежние каталоги, необходимые для BuildLock, либо явно объяснять невозможность воспроизведения.
- Пересматривать зависимости и ключи подписи; обновлять совместимость схем без потери проектов.
