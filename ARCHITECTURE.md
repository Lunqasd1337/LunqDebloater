# Как устроен LunqDebloater

English: [ARCHITECTURE.en.md](ARCHITECTURE.en.md)

Этот файл для тех, кто правит код: где что лежит, в каком порядке идёт сборка и как добавить новое, ничего не сломав. Как пользоваться скриптом, описано в [README.md](README.md), правила для PR в [CONTRIBUTING.md](.github/CONTRIBUTING.md).

## Структура репозитория

```text
LunqDebloater.ps1            Точка входа: параметры, пошаговый режим, проверки, план и контекст сборки
Start.cmd                    Запуск двойным щелчком (пошаговый режим)
Install.ps1                  Загрузчик для запуска одной командой (irm | iex)
Config\                      Всё, что пользователь настраивает под себя
  Profile.json               Профиль: что удалить и что записать в реестр
  Apps.txt                   Программы winget для первого входа
  Scripts\                   Свои *.ps1 для первого входа
  Drivers\                   Драйверы .inf (в git не попадают)
  Updates\                   Обновления .msu/.cab (в git не попадают)
    SafeOS\                  Safe OS Dynamic Update для WinRE
    Setup\                   Setup Dynamic Update для установщика
    Catalog\                 Скачанное из каталога Microsoft (-DownloadUpdates)
  README.txt, README.en.txt  Подсказка по папке Config
Modules\
  LunqDebloater\
    LunqDebloater.psd1       Манифест: версия и экспортируемые функции
    LunqDebloater.psm1       Подключает Private\*.ps1 и выбирает язык
    Private\*.ps1            Функции по темам (таблица ниже)
    Strings\ru\*.psd1        Тексты интерфейса на русском
    Strings\en\*.psd1        Те же ключи на английском
  FirstLogon\FirstLogon.ps1  Скрипт первого входа, который кладётся в образ
ThirdParty\
  EdgeRemover\              Скрипт he3als для удаления Edge, без изменений (анализатор его не проверяет)
Schemas\Profile.schema.json  JSON-схема профиля для VS Code
Tests\                       Тесты Pester и заглушки
.github\                     GitHub Actions, шаблоны issue и PR, CONTRIBUTING, SECURITY, CODE_OF_CONDUCT
```

## Модуль LunqDebloater

`LunqDebloater.psm1` подключает все `Private\*.ps1` по алфавиту и сразу выбирает язык по системе. Наружу видны только функции из `FunctionsToExport` в манифесте, и это ровно те, что вызывает `LunqDebloater.ps1`: тест в `Tests\Module.Tests.ps1` следит, чтобы лишних не было. Новую функцию, которую вызывает скрипт, добавьте туда же. Остальные доступны тестам через `& (Get-Module LunqDebloater) { ... }`.

| Файл | За что отвечает |
|---|---|
| `Console.ps1` | Вывод: `Write-Step` («Шаг N из M»), `Write-Section`, `Write-Info`, `Write-Check`, `Read-YesNo`, `Format-Size` |
| `Language.ps1` | Таблицы строк и язык: `Set-LunqLanguage`, `Get-LunqText`, `Get-LunqLocalized` для текстов профиля |
| `System.ps1` | Права администратора, один запуск за раз (`Enter-LunqRunLock`), лог (`Start-LunqLog`), метки шагов в логе DISM и его сжатие в конце запуска (`Compress-LunqDismLog`), архив для отчёта об ошибке (`New-LunqBugReport`), версия, `Invoke-Native` для внешних программ (вывод при ошибке попадает в лог), передача параметров при перезапуске |
| `Profile.ps1` | Чтение и проверка профиля, выбор профиля и категорий, сборка общих списков из включённых категорий (`Get-LunqEffectiveConfig`) |
| `Options.ps1` | Сводка «Что войдёт в образ» в пошаговом режиме: поиск обновлений и драйверов (`Find-LunqBuildInputs`), пункты по найденному (`New-LunqContentOptions`), их зависимости, переключение по номеру, пункты-действия (`Invoke-LunqContentAction`) и окно выбора папки (`Select-LunqFolder`) |
| `Iso.ps1` | Подключение ISO, список редакций, версия образа и проверка требований профиля, копирование содержимого ISO |
| `Checks.ps1` | Проверки до сборки: рабочая папка, итоговый ISO, место на дисках, остатки прошлого запуска, версия Windows на компьютере |
| `Image.ps1` | Экспорт редакции, пересжатие WIM (`Optimize-LunqWim`), очистка хранилища компонентов, поиск `oscdimg` и сборка ISO |
| `Servicing.ps1` | Обновления и драйверы: в систему, в WinRE (`Update-LunqRecovery`) и в установщик (`Update-LunqSetup`), Safe OS и Setup Dynamic Update и их распознавание по содержимому `.cab` (`Split-LunqDynamicUpdates`), выгрузка драйверов этого компьютера (`Export-LunqHostDrivers`) |
| `Removal.ps1` | Удаление Appx, компонентов (capabilities), отключение функций и удаление CBS-пакетов |
| `Uninstall.ps1` | Программы из поля `Uninstall` профиля, которые DISM не удалит из образа: таблица скриптов из `ThirdParty` (`$script:LunqUninstallers`), их запуск на этой Windows (`Remove-LunqPrograms`, откат через `Invoke-LunqUninstaller -Action Restore`) и раскладка в образ с `Uninstall.json` для первого входа (`Copy-LunqUninstallers`) |
| `Registry.ps1` | Офлайн-кусты реестра, запись и удаление значений и ключей, отметка о сборке в `HKLM\SOFTWARE\LunqDebloater` |
| `PostInstall.ps1` | Программы и скрипты первого входа: копирование в образ, `unattend.xml` в Sysprep |
| `Unattend.ps1` | `autounattend.xml` в корне ISO: регион, обход требований, локальная учётная запись |
| `Inventory.ps1` | Режим «Что в образе»: список Appx, компонентов и функций с пометками категорий профиля |
| `Build.ps1` | Шаги сборки (`Get-LunqBuildSteps`) и режима «Что в образе» (`Get-LunqInventorySteps`), их запуск по порядку (`Invoke-LunqBuild`) и значения отметки о сборке |
| `Report.ps1` | Общий формат результата шага (`New-LunqResult`) и итог сборки (`Write-LunqReport`) |
| `Catalog.ps1` | Свежие обновления из каталога Центра обновления: разбор страницы поиска и окна скачивания, выбор самого нового, скачивание с проверкой SHA-1 и кэшем (`Save-LunqCatalogUpdates`). Сеть только через `Invoke-LunqWebRequest`, тесты подменяют её |
| `Schedule.ps1` | Задание планировщика для пересборки по рецепту каждый месяц (`Register-LunqSchedule`, `Unregister-LunqSchedule`, через `schtasks.exe /XML`). Задание идёт от SYSTEM и запускает копию программы, `Config` и рецепта в `Program Files\LunqDebloater-Schedule` (`Copy-LunqScheduleFiles`), а не папку пользователя |
| `Recipe.ps1` | Рецепт сборки `<имя ISO>.lunq.json`: запись (`New-LunqRecipe`), чтение и проверка, параметры для повтора (`Get-LunqRecipeParameters`), сверка обновлений, отчёт «до и после» в HTML (`Write-LunqHtmlReport`) |
| `Restore.ps1` | Данные для отката: что удалено и как было в реестре, по категориям профиля (`New-LunqRestoreData`, `Add-LunqRestoreItem`), файл `Windows\LunqDebloater\Restore.json` и откат на этой Windows (`Invoke-LunqRestore`) |
| `Host.ps1` | Копия этого компьютера: программы из `winget export` (`Export-LunqHostApps`, `Merge-LunqAppsList`) и сети Wi-Fi (`Export-LunqHostWifi`) |

## Как идёт запуск

1. **Подготовка окружения** (`LunqDebloater.ps1`). Вне Windows скрипт сразу останавливается. В PowerShell 7 он перезапускает себя в Windows PowerShell 5.1, потому что часть командлетов DISM в 7 не работает. Без прав администратора в пошаговом режиме он предлагает перезапуск с повышением, с параметрами просто останавливается. Пути пересчитываются в полные, ведь новое окно может открыться в другой папке.
2. **Лог.** `Start-LunqLog` начинает лог в `Logs` рядом со скриптом и отдельный лог DISM. Всё дальнейшее, включая ошибки выбора ISO, попадает в лог.
3. **Выбор.** В пошаговом режиме пользователь выбирает действие (сборка или «Что в образе»), ISO, профиль и категории. С параметрами всё это берётся из параметров.
4. **Содержимое Config.** Находятся обновления (`Get-LunqUpdateFiles`), драйверы, программы и скрипты: обновления и драйверы ищет `Find-LunqBuildInputs`. Safe OS и Setup Dynamic Update берутся из подпапок `SafeOS` и `Setup`, а `.cab` в корне папки обновлений проверяет `Split-LunqDynamicUpdates`: из него распаковываются только `.mum`, нет `.mum` значит Setup Dynamic Update, `Package_for_SafeOSDU` значит Safe OS. В пошаговом режиме показывается сводка `Select-LunqBuildOptions` с пунктами из `New-LunqContentOptions`, где их можно включить и выключить. Пункты с `-Action` в ней не переключаются, а возвращают свой Key: `Invoke-LunqContentAction` выполняет действие (выбор папки через `Select-LunqFolder`, выгрузка драйверов `Export-LunqHostDrivers`), скрипт, заново ищет файлы и показывает сводку ещё раз. Выбор пользователя между показами хранится в `$choices`.
5. **Проверки** (`Test-LunqPrerequisites`): рабочая папка, итоговый ISO, место, `oscdimg`. Ошибка останавливает запуск до долгой работы.
6. **Редакция и версия.** ISO подключается один раз для списка редакций, выбора и версии выбранной, и ещё один раз на время работы с ним: шаги CopyIso и Export (или «Что в образе») держат его подключённым в `Context.State.Iso`, а `Dismount-LunqStateIso` отключает его после Export или при ошибке. `Test-LunqImageRequirements` сверяет сборку с `Requirements` профиля.
7. **Режим «Что в образе»** (`-ListContents`) на этом заканчивается: `Invoke-LunqBuild -Inventory` выполняет шаги `Get-LunqInventorySteps`, редакция монтируется только для чтения (если на ISO лежит `install.wim`, прямо с ISO, без экспорта; `install.esd` сначала экспортируется в рабочую папку), опись сохраняется рядом с ISO или, если туда не записать, в папку `Logs` (`Get-LunqContentsDir`), `Write-LunqInventory` сохраняет список, образ отключается без сохранения.
8. **План.** Скрипт показывает, что будет сделано, и в пошаговом режиме просит подтверждение.
9. **Сборка** по списку шагов (ниже), затем итог `Write-LunqReport`. После итога, уже не шагом, рядом с ISO пишутся рецепт и HTML-отчёт: сбой здесь не портит готовый ISO.
10. **При ошибке** кусты реестра выгружаются, образ отключается без сохранения. Рабочая папка удаляется, только если этот запуск сам её создал (шаг Prepare) и в ней ничего не смонтировано, иначе DISM потеряет образ.

Другие режимы ответвляются раньше. `-Schedule` (с `-Recipe`) только создаёт или удаляет задание. `-Recipe` в начале подставляет значения из рецепта во все параметры, не заданные в командной строке, и дальше идёт обычная сборка без вопросов. `-Restore` читает `Restore.json`, даёт выбрать категории и вызывает `Invoke-LunqRestore`. `-Online` проходит выбор профиля и категорий, как сборка, и выполняет `Invoke-LunqBuild -Online`: шаги `Get-LunqOnlineSteps` вызывают те же функции удаления и реестра с `-Online` вместо `-MountPath`, а программы из `Uninstall` удаляет сразу шаг Uninstall. `-DownloadUpdates` скачивает обновления после чтения редакции, когда известны выпуск и архитектура, и до проверки версии.

Перед каждым изменением функции удаления и `Set-LunqRegistry` записывают в `Context.Restore`, что убрано и как было (для `DeleteKey` выгрузка ключа через `reg export`). При сборке это сохраняется в образ на шаге Save, при `-Online` дописывается к `%SystemRoot%\LunqDebloater\Restore.json` последним шагом (и при ошибке тоже).

## Шаги сборки

Шаги описаны в `Private\Build.ps1` списком, который возвращает `Get-LunqBuildSteps`. У каждого есть `Name`, `Title`, `Hint`, `When` (выполнять ли) и `Run` (что делать). По `When` считается «Шаг N из M», поэтому номера всегда идут подряд.

`LunqDebloater.ps1` собирает всё, что нужно шагам, в одну хэш-таблицу, контекст сборки, и передаёт её в `Invoke-LunqBuild`. Каждый `Run` получает этот контекст параметром и возвращает результаты, `Invoke-LunqBuild` собирает их для итога. В `Context.State` шаги отмечают то, что нужно знать при ошибке: смонтирован ли образ (`Mounted`) и создал ли запуск рабочую папку (`WorkDirOwned`). Скрипт читает эту же таблицу в `catch` и `finally`. В модуле включён `StrictMode`, поэтому в контексте должны быть все ключи, даже пустые.

| Шаг | Что делает | Когда |
|---|---|---|
| Prepare | Очищает рабочую папку (`Reset-LunqWorkDir`) | всегда |
| CopyIso | Подключает ISO (до конца шага Export) и копирует его содержимое в `WorkDir\iso`, кроме `install.wim` и `install.esd` | всегда |
| Export | Экспортирует выбранную редакцию прямо из подключённого ISO в отдельный `install.wim` (ESD становится WIM) с быстрым сжатием и отключает ISO: максимальное сжатие делает шаг Recompress | всегда |
| Mount | Монтирует `install.wim` в `WorkDir\mount` | всегда |
| Updates | Ставит обновления по возрастанию KB | есть обновления |
| Drivers | Добавляет драйверы по одному `.inf` | есть драйверы |
| Recovery | Обслуживает `Winre.wim` внутри системы: обновления, Safe OS DU, драйверы дисков | `-UpdatesToSetup` или `-DriversToSetup`, и есть что ставить в WinRE |
| FirstLogon | Кладёт программы, скрипты, скрипты удаления из `Uninstall` и `FirstLogon.ps1` в `Windows\Setup\Scripts\Lunq` | есть программы, скрипты или `Uninstall` во включённых категориях |
| Unattend | Кладёт `autounattend.xml` в корень ISO | файл ответов включён |
| Appx | Удаляет Appx из профиля | без `-SkipAppx` |
| Capabilities | Удаляет компоненты | без `-SkipComponents` |
| Features | Отключает функции и удаляет CBS-пакеты | без `-SkipComponents` |
| Registry | Применяет записи реестра профиля | без `-SkipRegistry` |
| Cleanup | Очищает хранилище компонентов (`dism /StartComponentCleanup /ResetBase`) | `-CleanupComponents` |
| Save | Пишет отметку о сборке в реестр образа и данные для отката в `Windows\LunqDebloater\Restore.json`, сохраняет `install.wim` | всегда |
| Setup | Распаковывает Setup DU в `sources`; если для `boot.wim` (образ 2) есть обновления или драйверы, обслуживает его и копирует из него `setup.exe`, `setuphost.exe` и загрузчик UEFI | есть что ставить в установщик |
| Recompress | Пересжимает `install.wim` | всегда |
| Iso | Собирает загрузочный ISO через `oscdimg` | всегда |

Порядок важен: обновления ставятся до удаления компонентов, файл ответов и отметка о сборке пишутся до сохранения образа, а установщик обслуживается после, потому что он лежит в `WorkDir\iso`, а не внутри `install.wim`.

## Результат шага и итог

Каждая функция шага возвращает объект `New-LunqResult`: `Title`, `Kind`, списки `Done`, `Failed`, `Skipped`, `NotMatched`, строку `Summary` и счётчики `ByCategory`. `Write-LunqReport` выводит их одинаково для всех шагов: удаления и реестр по категориям профиля, остальное строкой «установлено/добавлено N, ошибок M». Ошибка одного пакета или драйвера попадает в `Failed` и не срывает сборку. Пакет, который DISM отверг как неподходящий к образу (`0x800f081e`, `Test-LunqNotApplicable`), попадает в `Skipped`, и итог показывает его отдельной строкой. Ошибка, после которой продолжать нельзя, бросается исключением.

## Профиль

`Read-LunqProfile` читает JSON, проверяет поля и записи реестра (тип, число, действие) и приводит тексты к языку интерфейса через `Get-LunqLocalized`. `Get-LunqEffectiveConfig` собирает включённые категории в общие списки `Appx`, `Capabilities`, `Features`, `Packages` и `Registry`. У каждой записи реестра остаётся `LunqCategory`, чтобы итог считался по категориям. Имена сравниваются шаблонами `-like` (`Test-NamePattern`), а шаблоны, которые ничего не нашли, попадают в `NotMatched`.

## Реестр образа

`Mount-OfflineHives` подключает кусты смонтированного образа под своими именами и всегда выгружает их в `finally`:

| Hive в профиле | Подключается как | Файл в образе |
|---|---|---|
| `SOFTWARE` | `HKLM\LUNQ_SOFTWARE` | `Windows\System32\config\SOFTWARE` |
| `SYSTEM` | `HKLM\LUNQ_SYSTEM` | `Windows\System32\config\SYSTEM` |
| `DefaultUser` | `HKLM\LUNQ_NTUSER` | `Users\Default\NTUSER.DAT` |

Подключение и выгрузка идут через `reg.exe`, а значения пишутся через .NET (`Set-LunqRegistryValue`), чтобы кавычки и `\` в конце не искажались. Действия записи: установить значение (по умолчанию), `DeleteValue`, `DeleteKey`.

## Тексты интерфейса

Всё, что видит пользователь, берётся через `Get-LunqText 'Область.Имя' аргументы...` из `Strings\<язык>\<Область>.psd1`. Область совпадает с именем файла в `Private` (`Main` для самого скрипта). Строка всегда проходит через `-f`, поэтому фигурные скобки в тексте пишутся удвоенными. Язык выбирается параметром `-Language`, по умолчанию русский на русской Windows и английский на остальных.

`FirstLogon.ps1` работает в установленной системе без модуля, поэтому его строки лежат в таблице `$texts` внутри файла. Язык он берёт из `Language.txt`, который записывает `Install-LunqFirstLogon`.

| `Tests\Steps.Tests.ps1` | Шаги сборки по отдельности: какие выполняются при каких настройках, отдельный шаг с заглушкой, отметка о сборке |
| `Tests\Install.Tests.ps1` | Загрузчик: раскладка релиза, обновление с сохранением правок в `Config`, работа без сети |

| `Tests\Uninstall.Tests.ps1` | Удаление программ из `Uninstall`: запуск скрипта из `ThirdParty` с нужными параметрами, `Uninstall.json` для образа, параметры EdgeRemover |
| `Tests\Registry.Tests.ps1` | Разбор значений реестра из профиля и настоящая запись в реестр (запись только в Windows) |

| `Tests\Mocks\TestMocks.ps1` | Заглушки функций модуля, которые трогают систему: права администратора, подключение ISO, место на дисках, `Invoke-Native` (robocopy, reg.exe, oscdimg, expand.exe), окно выбора папки и запись в реестр. Копируется в модуль копии скрипта как `Private\ZZ.TestMocks.ps1`, чтобы подключиться последним |

Поведение заглушек настраивается переменными `LUNQ_TEST_*`: например, `LUNQ_TEST_DISM_EXIT` (код выхода dism.exe), `LUNQ_TEST_FAIL_APPX` (сбой посреди сборки), `LUNQ_TEST_IMAGE_VERSION`, `LUNQ_TEST_HOST_BUILD`, `LUNQ_TEST_NOT_ADMIN`, `LUNQ_TEST_FOLDER` (что «выбрано» в окне выбора папки), `LUNQ_TEST_NO_HOST_DRIVERS`, `LUNQ_TEST_ISO_WIM` (на ISO `install.wim` вместо `install.esd`). Вызовы внешних программ пишутся в `LUNQ_TEST_NATIVE_LOG`, записи реестра в `LUNQ_TEST_REG_LOG`, и тесты сверяют их. Сквозные тесты по умолчанию идут на русском и сравнивают русский вывод, английские тесты проверяют, что в выводе нет кириллицы.

## Как добавить

**Параметр.** Добавьте его в `param()` в `LunqDebloater.ps1` и в таблицу параметров в `README.md` и `README.en.md` (тест это проверяет). Если это путь, добавьте имя в `$pathParams`, чтобы при перезапуске он передался полным.

**Шаг сборки.** Добавьте запись в `Get-LunqBuildSteps` (`Private\Build.ps1`) на правильное место, строки `Main.Step<Имя>` и `Main.Step<Имя>Hint` в обе таблицы. `Run` получает контекст параметром и возвращает `New-LunqResult`. Если шагу нужно новое значение, добавьте ключ в контекст в `LunqDebloater.ps1` и в `New-TestContext` в `Tests\Steps.Tests.ps1`. Поправьте списки шагов в `Tests\Steps.Tests.ps1` и ожидаемое число шагов в `Tests\Build.Tests.ps1`.

**Строку интерфейса.** Добавьте ключ в `Strings\ru\<Область>.psd1` и `Strings\en\<Область>.psd1` с одинаковыми `{0}`, `{1}`. Ключи в таблице выровнены по самому длинному.

**Запись в профиль.** Допишите имя в нужный список категории `Config\Profile.json` (списки отсортированы) или новую категорию с `Name` и `Description` на двух языках. Если меняется поведение профиля по умолчанию, поправьте описание категории и раздел «Профиль» в обоих README.

**Внешнюю программу.** Вызывайте её через `Invoke-Native`: так stderr не превращается в исключение в 5.1, а тесты могут подменить вызов. Добавьте ветку в заглушку `Invoke-Native` в `Tests\Mocks\TestMocks.ps1`, если скрипт потом ищет результат этой программы.

## Загрузчик Install.ps1

`Install.ps1` не зависит от модуля. Пользователь получает его командой `irm <raw-ссылка на main> | iex`, а загрузчик уже скачивает архив последнего релиза. Поэтому сам загрузчик берётся из `main`, а программа приходит только из выпущенной версии.

В отличие от остальных скриптов он хранится в ASCII без BOM, поэтому его сообщения и комментарии на английском. `irm` отдаёт файл в `iex` строкой, и как её раскодирует Windows PowerShell 5.1, зависит от заголовков ответа. BOM мог бы попасть в начало кода, а русские буквы при неверной кодировке могут дать «умные» кавычки и сломать разбор. Тест `Tests\Install.Tests.ps1` проверяет, что в файле только ASCII.

В `.lunq-install.json` рядом с программой загрузчик хранит тег установленного релиза и хэши файлов `Config`, которые он положил. Файл `Config`, чей хэш с тех пор изменился, считается правкой пользователя и при обновлении не заменяется.

## Версии и выпуск

Версия задаётся только в `ModuleVersion` манифеста. Её видно в заголовке окна, в логе, в итоге и в отметке о сборке. Заметное пользователю изменение записывается в [CHANGELOG.md](CHANGELOG.md) под новой версией: новая возможность поднимает вторую цифру, исправление или небольшая правка профиля третью. После слияния в `main` на GitHub создаётся тег `vX.Y.Z` и релиз с текстом из CHANGELOG.
