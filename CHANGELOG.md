# Изменения

Версия LunqDebloater видна в заголовке окна, в логе, в итоге сборки и в реестре собранного образа (`reg query HKLM\SOFTWARE\LunqDebloater`).

## 1.9.2

Исправления по разбору проекта.

- Второй запуск, пока идёт первый, останавливается сразу с понятным сообщением. Раньше подготовка второго запуска (например, «Что в образе» во время сборки) отключала смонтированный образ первого, удаляла его рабочую папку и выгружала его кусты реестра.
- Если DISM не ответил, смонтированы ли образы, рабочая папка больше не удаляется: скрипт считает, что образ в ней может быть смонтирован, и просит перезагрузить компьютер или выполнить `dism /Cleanup-Wim`.
- Если куст реестра образа не выгрузился за пять попыток, сборка останавливается с объяснением. Раньше она шла дальше и терялась на сохранении образа с непонятной ошибкой DISM.
- Если для установщика есть только Setup Dynamic Update (или только Safe OS Dynamic Update), boot.wim больше не монтируется и не пересжимается, а `setup.exe` из Setup Dynamic Update не заменяется старым из boot.wim. Это экономит несколько минут.
- После обновления boot.wim загрузчик UEFI на ISO (`efi\boot\bootx64.efi` или `bootaa64.efi` и `bootmgr.efi`) берётся из обновлённого WinPE, как в инструкции Microsoft по обновлению носителя.
- `Install.ps1` не принимает клон репозитория (папку с `.git`) за прежнюю установку: раньше он заменял в ней `Modules`, `Tests` и другие папки целиком.
- Тесты первого входа в обычном окне Windows больше не перезапускают скрипт через UAC (это ставило настоящие программы и регистрировало настоящее задание).
- `"Enabled": "false"` или `"RemoveFeaturePayload": "false"` в кавычках больше не значат «включено»: такой профиль отвергается с понятным текстом. Раньше категория `drivers` с `"false"` в кавычках включалась, и новая система могла остаться без драйвера сети.
- Языковые пакеты и компоненты по запросу (пакеты без номера KB) ставятся до накопительного обновления, а обновления .NET после него, как в инструкции Microsoft. Раньше языковой пакет ставился последним и оставался в исходной версии.
- Драйверы этого компьютера, выгруженные для сборки, удаляются из `%TEMP%` в конце запуска. С драйвером видеокарты это 1–3 ГБ на системном диске.
- `Install.ps1` оставляет право менять папку программы только вам, администраторам и SYSTEM. Раньше папка в корне диска (например, `-Path D:\LunqDebloater`) наследовала права, с которыми любой пользователь компьютера мог подменить скрипт, а запускается он с правами администратора.
- Если на первом входе не удалось закрыть скрипты и лог от других пользователей, это пишется в лог. В README добавлено предупреждение: внутри ISO скрипты первого входа не защищены.
- Чужой `autounattend.xml` в ISO останавливает сборку до её начала, а чужой `Sysprep\unattend.xml` в образе сразу после монтирования. Раньше это обнаруживалось после обновлений, драйверов и WinRE.
- Прошлый ISO, подключённый в Проводнике как диск, обнаруживается в проверках перед сборкой, а не на последнем шаге. oscdimg пишет во временный файл `*.partial.iso` и заменяет итоговый ISO только после успеха: при сбое прошлый ISO остаётся целым.
- Сборка быстрее: выбранная редакция экспортируется прямо из подключённого ISO с быстрым сжатием (итоговый `install.wim` по-прежнему сжимается максимально), а robocopy больше не копирует `install.esd` в рабочую папку, чтобы потом его удалить. С ISO на 5–7 ГБ это экономит гигабайты записи на диск.
- Сводка перед сборкой не перечитывает каждый раз все `.inf` драйверов, чтобы найти драйверы контроллеров дисков для установщика: ответ запоминается до изменения файла.
- Тесты и CI работают быстрее: подставной winget собирается один раз, а CI ставит Pester и PSScriptAnalyzer только если подходящей версии нет на раннере. Заодно исправлен редкий ложный провал теста полной сборки: заглушка DISM отклоняла все драйверы, если в случайном имени временной папки встречалось «bad».

## 1.9.1

- Лог DISM в конце запуска сжимается в `LunqDebloater_<дата>_dism.zip`. Со встраиванием обновлений он вырастал до сотен мегабайт, а сжатый занимает в десятки раз меньше. Открыть его можно двойным щелчком в Проводнике.
- Лог DISM больше 20 МБ попадает в архив для отчёта об ошибке сокращённым: сначала все ошибки, предупреждения и метки шагов, затем последние 20 000 строк. Так архив помещается в issue на GitHub, а полный лог остаётся в папке `Logs`.

## 1.9.0

Логи стали подробнее, а отчёт об ошибке собирается сам.

- Если внешняя программа (robocopy, reg, expand, oscdimg и другие) завершилась с ошибкой, её последние строки вывода попадают в лог. Раньше было видно только код выхода.
- При ошибке под её текстом показано, где она произошла: цепочка вызовов с именами функций и номерами строк.
- У заголовка каждого шага указано время начала, а в итоге строка «Дольше всего» с тремя самыми долгими шагами.
- В логе DISM перед каждым шагом стоит метка `===== LunqDebloater <время>: step N/M: <шаг> =====`: по ней легко найти нужное место в большом файле.
- Если сборка прервалась ошибкой, рядом с логом появляется архив `LunqDebloater_<дата>_report.zip`: лог запуска, лог DISM и профиль. Путь к папке пользователя, имя пользователя и имя компьютера в нём заменены на `%USERPROFILE%`, `<user>` и `<computer>`, поэтому для отчёта достаточно приложить один этот файл.

## 1.8.1

- Обновление, которое не подходит к образу (DISM отвечает `0x800f081e`), пропускается спокойно и не считается ошибкой: в итоге оно в отдельной строке «Не подходят к этому образу». Так бывает с Safe OS Dynamic Update, положенным рядом с обычными обновлениями: он ставится только в WinRE. Если такой `.cab` лежит не в подпапке, скрипт подсказывает переложить его в `SafeOS` или `Setup`. Предупреждения DISM больше не повторяют сообщение скрипта.
- Safe OS и Setup Dynamic Update узнаются по содержимому `.cab`, если лежат в корне папки обновлений, например в «Загрузках», выбранных в сводке. Подпапки `SafeOS` и `Setup` для этого больше не нужны: Safe OS Dynamic Update идёт только в WinRE, Setup Dynamic Update распаковывается в установщик, а сводка помечает такие файлы. Для проверки из `.cab` распаковываются только файлы `.mum`.

## 1.8.0

- Пошаговый режим: драйверы и обновления больше не нужно класть в `Config`. В сводке «Что войдёт в образ» появились пункты «Выбрать папку с обновлениями» и «Выбрать папку с драйверами» (окно выбора папки, например «Загрузки» или флешка с драйверами производителя) и «Взять драйверы с этого компьютера» (`Export-WindowsDriver -Online`). После выбора сводка показывается снова и сохраняет остальной выбор. Под найденными драйверами и обновлениями видно, из какой они папки.

## 1.7.0

- Запуск одной командой: `irm https://raw.githubusercontent.com/Lunqasd1337/LunqDebloater/main/Install.ps1 | iex`. Команда скачивает последний релиз в `C:\Users\<имя>\LunqDebloater` и запускает скрипт. Повторный запуск обновляет программу и не заменяет изменённые вами файлы в `Config`.

## 1.6.1

Поведение сборки не меняется, это перестройка кода для тех, кто его правит.

- Шаги сборки перенесены из `LunqDebloater.ps1` в модуль (`Modules\LunqDebloater\Private\Build.ps1`). Скрипт собирает настройки в один контекст сборки и передаёт его модулю, поэтому каждый шаг можно проверить отдельно (`Tests\Steps.Tests.ps1`).
- Общий файл тестов `Tests\Unit.Tests.ps1` разбит по областям: `Module`, `Profile`, `Checks`, `Servicing` и `PostInstall`. Разбор значений реестра проверяется в `Registry.Tests.ps1`.
- `CONTRIBUTING.md`, `SECURITY.md` и `CODE_OF_CONDUCT.md` перенесены в папку `.github`.

## 1.6.0

- Рабочая папка удаляется в конце, только если этот запуск сам её создал. Раньше папка, которую проверка отвергла (не пустая и не созданная скриптом), удалялась целиком, если в ней была подпапка `iso`. То же было с папкой от прошлого `-KeepWorkDir`, если ответить N перед сборкой.
- Доступ к рабочей папке есть только у администраторов и SYSTEM: обычный пользователь компьютера не может подменить файлы образа во время сборки.
- Setup Dynamic Update: если в `Updates\Setup` несколько файлов, распаковывается каждый `.cab`, а `.msu` пропускаются. Раньше фильтр видел весь список одним объектом.
- ISO для ARM64 собирается: без загрузчика BIOS (`etfsboot.com`) ISO делается только для UEFI. Раньше сборка падала на последнем шаге.
- Модуль загружается из папки, в пути к которой есть `[` или `]`.
- Обновление .NET не считается накопительным обновлением Windows при проверке версии образа.
- `-Label` проверяется сразу: латинские буквы, цифры, `_` и `-`, до 32 символов.
- Запись реестра без `Type` даёт понятную ошибку при чтении профиля.
- Первый вход: задание повторной попытки запускается и от батареи и не останавливается при отключении зарядки. Скрипты пользователя ждут, пока поставятся программы (на последней попытке или если задание повторной попытки создать не удалось, выполняются сразу). Скрипты пользователя и лог первого входа доступны только администраторам.
- Профиль: убраны записи, которых нет в Windows 11 26H2 (People, компонент Quick Assist, Internet Explorer, PowerShell 2.0). Службы XPS (`Printing-XPSServices-Features`) больше не отключаются.
- Тесты и CI: заглушки DISM проверяют имена параметров, анализатор ловит параметры командлетов, которых нет в 5.1, Pester ограничен версией 5.

## 1.4.0

- Safe OS Dynamic Update и Setup Dynamic Update: их можно положить в подпапки `Config\Updates\SafeOS` и `Config\Updates\Setup`. Вместе с `-UpdatesToSetup` Safe OS ставится в WinRE после накопительного обновления, а Setup Dynamic Update распаковывается в `sources` ISO, как в инструкции Microsoft.
- После обновления установщика `setup.exe` и `setuphost.exe` копируются из `boot.wim` в `sources` ISO. Раньше с `-UpdatesToSetup` они могли не совпасть с версиями внутри `boot.wim`, и установка могла не запуститься.

## 1.3.0

- Английский интерфейс. Язык выбирается параметром `-Language ru|en`, по умолчанию русский на русской Windows и английский на остальных. Скрипт первого входа говорит на языке сборки. Названия и описания в профиле могут быть на двух языках: `{ "ru": "...", "en": "..." }`.
- Предупреждение «на свой страх и риск» в README, в `Config\README.txt` и перед началом сборки.
- JSON-схема профиля (`Schemas/Profile.schema.json`): подсказки и проверка в VS Code.
- English README (`README.en.md`), `CONTRIBUTING.md`, шаблоны issue на GitHub.
- Справка `Get-Help` стала короткой и двуязычной: подробное описание параметров теперь только в README, а `Get-Help -Online` открывает его на GitHub.

## 1.2.0

- Тесты Pester и проверка PSScriptAnalyzer в GitHub Actions на каждый PR (Windows PowerShell 5.1 и PowerShell 7).
- Очистка хранилища компонентов идёт через `dism.exe`: в модуле DISM старых Windows 10 у `Repair-WindowsImage` нет нужных параметров, и сборка обрывалась в конце. Неудачная очистка больше не срывает сборку.
- Предупреждение, если Windows на компьютере старше образа: DISM такой системы может не справиться с обновлениями.
- Записи реестра пишутся через .NET, а не через `reg.exe`: значения с кавычками и `\` в конце больше не искажаются. Ошибки в записях профиля (тип, число, действие) видны сразу при чтении профиля.
- Файл ответов задаёт все поля первой страницы установщика, и она больше не показывается.
- Остатки прерванного запуска в своей рабочей папке больше не дают предупреждения.
- ISO, уже открытый в Проводнике, не отключается скриптом.
- Рабочая папка может содержать пробел.
- oscdimg ищется и в папке ADK для ARM64.
- Скрипт после установки с ненулевым кодом выхода считается неудачным.
- Категория `drivers` выключена по умолчанию; из профиля убраны записи для Cortana и WordPad, которых нет в 26H2.
- Модуль разложен по файлам в `Modules\LunqDebloater\Private`, появился манифест с версией.
- Справка `Get-Help` описывает все параметры. Добавлены лицензия MIT и этот файл.
