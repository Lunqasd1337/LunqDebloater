# Изменения

Версия LunqDebloater видна в заголовке окна, в логе, в итоге сборки и в реестре собранного образа (`reg query HKLM\SOFTWARE\LunqDebloater`).

## 1.14.0

- **Ежемесячная пересборка по расписанию убрана.** Параметра `-Schedule` больше нет, и пошаговый режим больше не предлагает пересборку в конце. Задание работало от имени SYSTEM, а итоговый ISO, рецепт и отчёт писало в папку, которую выбрал пользователь: подменённая в ней ссылка на другую папку позволяла записать файл от SYSTEM куда угодно. К тому же после обновления LunqDebloater задание продолжало запускать свою старую копию программы. Свежий ISO по-прежнему собирается одной командой: `.\LunqDebloater.ps1 -Recipe <рецепт> -DownloadUpdates -Force`, её можно запускать раз в месяц самому.
- **Старые задания удаляются сами.** Любой запуск новой версии (сборка, `-Online`, `-Restore`, «Что в образе») удаляет задания `LunqDebloater\...` из планировщика и копии программы в `C:\Program Files\LunqDebloater-Schedule`, если они остались от прошлых версий. Если задание было, запустите новую версию один раз. Если удалить не получилось, скрипт предупредит и попробует снова в следующий раз.

## 1.13.1

- **Сводка «Что войдёт в образ» по разделам.** Пунктов в сводке стало два десятка, и они шли одним длинным списком. Теперь главный экран показывает пять разделов: «Обновления», «Драйверы», «Первый вход», «Установка Windows» и «Дополнительно», и в строке каждого видно, что в нём включено. Номер открывает раздел с его пунктами, Enter возвращает к разделам. Редкие пункты (очистка хранилища компонентов, загрузчик CA 2023, части для FAT32, сборка без проверки Defender) собраны в «Дополнительно». Номера пунктов теперь свои в каждом разделе.

## 1.13.0

- **Загрузчик Windows UEFI CA 2023.** Новый параметр `-BootCA2023` (пункт в конце сводки) кладёт на ISO загрузчик, подписанный новым сертификатом Microsoft: такой носитель грузится с Secure Boot и на компьютерах, где старый сертификат Windows Production PCA 2011 уже отозван. Файлы берутся из обновлённого образа, поэтому нужно накопительное обновление, а установщик обновляется вместе с системой. Носитель не загрузится с Secure Boot там, где в DB нет сертификата 2023 года, поэтому по умолчанию параметр выключен. Подробнее в разделе README «Загрузчик и Secure Boot».
- **`efisys.bin` обновляется вместе с загрузчиком.** После обновления установщика на ISO менялись `bootx64.efi` и `bootmgr.efi`, а `efisys.bin`, из которого `oscdimg` делает загрузочный образ UEFI, оставался из исходного ISO. ISO, подключённый к виртуальной машине напрямую, грузился старым загрузчиком. Теперь `efisys.bin` берётся из того же `boot.wim`.
- **Локальная учётная запись создаётся при установке.** Новый параметр `-LocalAccountName` (в пошаговом режиме имя спрашивается после сводки) создаёт учётную запись администратора с этим именем прямо из файла ответов, и Windows больше не показывает экран учётной записи. Группа «Администраторы» берётся по SID, поэтому это работает и на русской Windows. Пароль в ISO не хранится: при первом входе окно первичной настройки предлагает его задать, Enter оставляет учётную запись без пароля. `-LocalAccount` без имени работает как раньше.
- **Образ для флешки FAT32.** Новый параметр `-SplitWim` делит `install.wim` на части `install.swm` по 3800 МБ, и ISO можно записать на флешку FAT32 простым копированием. Без него итог предупреждает, если `install.wim` больше 4 ГБ, и подсказывает Rufus или `-SplitWim`.
- **Программы ставятся для всех пользователей.** Первый вход ставит программы из `Apps.txt` с `--scope machine`, и они есть у всех учётных записей компьютера, а не только у той, что вошла первой. Если у программы нет установщика для всех, она ставится как раньше. Своё `--scope` в строке `Apps.txt` главнее.
- **Ваши скрипты идут в отдельном процессе.** Скрипты из `Config\Scripts` выполнялись внутри скрипта первого входа, и `$ErrorActionPreference`, переменные или `exit` одного скрипта могли повлиять на следующие. Теперь каждый запускается в своём PowerShell из той же папки, как скрипты удаления программ. Необработанная ошибка в скрипте теперь видна как код выхода 1, её текст попадает в окно и в лог. Если ваш скрипт пользовался переменными скрипта первого входа, это больше не работает.
- **Windows PE в `boot.wim` тоже обновляется.** С `-UpdatesToSetup` обновления ставились только в образ 2 `boot.wim` («Установка Windows»), а образ 1 (Windows PE, его берут для загрузки по сети) оставался старым. Теперь в него ставятся те же обновления, без драйверов, как в инструкции Microsoft.
- **Сборка без проверки Defender.** Новый параметр `-DefenderExclusion` (пункт в конце сводки) исключает рабочую папку из проверки Microsoft Defender до конца сборки: DISM пишет в неё десятки тысяч файлов, и проверка каждого замедляет сборку. Исключение убирается в конце, и после ошибки тоже, а если запуск убили, его уберёт следующий. Папку, которую вы исключили сами, LunqDebloater не трогает. По умолчанию параметр выключен.
- **Своё имя ISO и версия в имени.** Итоговый ISO теперь называется `<исходный>_Lunq_<версия>.iso`, например `Win11_26H2_Lunq_1.13.0.iso`: по имени видно, какой версией LunqDebloater он собран. В пошаговом режиме после сводки скрипт спрашивает своё имя, а с параметрами его задаёт новый `-OutputName`, версия добавляется в обоих случаях. `-OutputIso` по-прежнему задаёт полный путь как есть, без версии. В рецепт пишется имя без версии, поэтому повтор новой версией LunqDebloater собирает ISO с её номером, а задание по расписанию для рецепта новой версии заменяет прежнее, а не создаётся второе. Рецепты прошлых версий собирают ISO под старым именем.
- Скрипт первого входа, его задание повтора и удаление программ в `-Online` запускают Windows PowerShell по полному пути, а не первый `powershell.exe` из `PATH`.
- Выпуски Windows (номер сборки, название и пакет включения) собраны в одну таблицу `Modules\LunqDebloater\Data\Releases.psd1`: новый выпуск добавляется в одном месте. В ней только Windows 11 начиная с 24H2: Windows 10 и Windows 11 21H2–23H2 скрипт больше не называет, свежие обновления для них не скачивает, а их пакеты включения (KB5015684, KB5027397) ставятся вместе с накопительными.
- **Пакет включения 26H2 (KB5121794).** Он переводит 24H2 и 25H2 на 26H2 и теперь ставится отдельно, после накопительного обновления, как пакеты 25H2 и 23H2. Раньше его номер был неизвестен, и KB5121794 из `Config\Updates` шёл вместе с накопительными обновлениями.

## 1.12.0

- **Задание по расписанию запускает закрытую копию программы.** Задание `-Schedule Monthly` идёт от SYSTEM, а раньше запускало скрипт из папки программы (по умолчанию в профиле пользователя) и рецепт рядом с ISO. Любая программа, запущенная от имени пользователя, могла поменять эти файлы и выполнить свой код от SYSTEM. Теперь `-Schedule Monthly` копирует LunqDebloater, `Config` (без `Updates` и `Drivers`) и рецепт в `C:\Program Files\LunqDebloater-Schedule\<имя ISO>`, где менять файлы могут только администраторы, и задание запускает эту копию. После обновления LunqDebloater или правки `Config` запустите `-Schedule Monthly` ещё раз. `-Schedule Off` удаляет копию вместе с заданием. Существующие задания пересоздайте командой `-Schedule Monthly`.
- **Загрузчик не ставит программу в чужую папку.** Если папку установки (например, `D:\LunqDebloater`) или файлы в ней создал другой пользователь компьютера, `Install.ps1` отказывается от неё: владелец файла всегда может вернуть себе права на него, и его код потом выполнялся бы от имени администратора.
- Рабочая папка сборки теперь принадлежит администраторам, а не тому, кто её создал.
- **Ctrl+C и сбои больше не теряют данные отката.** `-Online` записывает в `Restore.json`, что было до изменений, после каждого шага, а не только в конце: после ошибки, Ctrl+C или закрытого окна `-Restore` вернёт то, что уже удалено.
- **Ctrl+C не оставляет смонтированные образы.** Раньше образ отбрасывался только при ошибке, а при Ctrl+C `install.wim` оставался смонтированным и занимал 10-20 ГБ до следующего запуска. Теперь после ошибки или прерывания отбрасываются все образы в рабочей папке, в том числе WinRE и boot.wim.
- **`Restore.json` не портится при оборванной записи.** Файл пишется через временный, прошлая версия хранится в `Restore.json.bak`. Если файл всё же испорчен, он откладывается как `Restore.json.corrupt-<время>`, а данные берутся из прошлой версии.
- После удачного `-Restore` файл отката обновляется и тогда, когда куст реестра не удалось выгрузить: следующий `-Restore` не повторит уже сделанное.
- **Рецепт без категорий повторяется без категорий.** Если в сборке были выключены все категории (например, нужны были только обновления и драйверы), повтор по рецепту и задание по расписанию включали категории по умолчанию из профиля и начинали удалять приложения. Теперь пустой список категорий в рецепте значит «ничего не удалять».
- **Пакет включения ставится по-настоящему.** Пакет включения (KB5054156 для 25H2, KB5027397 для 23H2, KB5015684 для Windows 10 22H2) попадал в общую папку накопительных обновлений, DISM его оттуда не брал, а итог писал, что он встроен. Теперь он ставится отдельно, после накопительных обновлений.
- Setup Dynamic Update больше не затирается старым `setup.exe`: файлы установщика копируются из boot.wim, только если в него встали обновления, а не после одних драйверов.
- **Первый вход не повторяется бесконечно.** Скрипт из `Config\Scripts`, который перезагружал компьютер или завершал процесс, запускался при каждом входе, а задание и копии скриптов с паролями не удалялись никогда. Теперь скрипт, который дважды начался и не дошёл до конца, пропускается (то же для удаления программ из профиля), а если попытки кончились, а задание осталось, следующий вход только убирает за собой.
- **Скачанные обновления проверяются строже.** Файл из каталога скачивается только с серверов загрузки Microsoft (`*.windowsupdate.com`, `*.delivery.mp.microsoft.com`, всегда по https) и только если в каталоге есть его контрольная сумма: раньше файл без суммы принимался без проверки. Setup Dynamic Update, скачанный или положенный в `Config\Updates` вручную, распаковывается в установщик, только если он подписан Microsoft.
- **Свежее обновление не теряется за первой страницей каталога.** Поиск отдаёт только 25 строк, и раньше свежее накопительное обновление могло на них не попасть, а скрипт молча брал старое. Теперь сначала ищутся обновления этого месяца, потом прошлого и только потом без месяца.
- **Загрузчик проверяет архив релиза.** К каждому релизу теперь прикладываются архив программы, `SHA256SUMS` и аттестация GitHub, а `Install.ps1` сверяет архив с суммой до распаковки и при несовпадении ничего не меняет. Для релизов до 1.12.0, где суммы нет, он предупреждает, что архив не проверен.
- **Пароли Wi-Fi и файлы рядом со скриптами закрыты уже в образе.** Раньше их закрывал от других пользователей сам первый вход, и если окно UAC отклоняли, они оставались доступны всем. Теперь папки `User` и `Wifi` получают права «только администраторы» при сборке.
- **Откат значения из двух категорий возвращает настоящее исходное.** Если одно значение реестра меняли две категории профиля, вторая запоминала как «исходное» то, что записала первая, и `-Restore` оставлял значение первой категории. Теперь запоминается только состояние до первого изменения.
- **`-Restore` возвращает приложение и новым пользователям.** Раньше приложение регистрировалось обратно только для того, кто запустил `-Restore`. Теперь оно снова подготавливается для всех новых учётных записей, а если это не удалось, `-Restore` предупреждает и даёт ссылку на приложение в Microsoft Store.
- **Непонятный `.cab` в папке обновлений не распаковывается в установщик.** Раньше любой `.cab` без описания пакета (например, драйвер) считался Setup Dynamic Update и распаковывался в `sources` ISO. Теперь Setup Dynamic Update узнаётся по `setupprep.exe` или `setuphost.exe` внутри, а остальное пропускается с предупреждением.
- **Без вопросов сборка не начинается при нехватке места.** Раньше нехватка места на диске рабочей папки или итогового ISO была только предупреждением, и запуск по расписанию шёл до ошибки DISM через полчаса. Теперь такой запуск останавливается до сборки, а новый параметр `-IgnoreSpace` позволяет начать всё равно. В пошаговом режиме по-прежнему решаете вы.
- Рабочая папка, которая оказалась ссылкой (junction или symlink), отвергается, а ссылки внутри старой рабочей папки удаляются сами по себе, без того, на что они указывают.
- **Обрыв сети не останавливает скачивание обновлений.** Файл из каталога скачивается до трёх раз, в том числе если пришёл испорченным, и только потом сборка останавливается.
- **Задания по расписанию для одноимённых рецептов больше не затирают друг друга.** Имя задания теперь `LunqDebloater\<имя ISO>-<отпечаток пути рецепта>`, поэтому `Win11.lunq.json` в двух папках получают два задания. `-Schedule Monthly` и `-Schedule Off` удаляют и задание старого формата с тем же именем: оно запускало папку программы, которую может менять пользователь. Если оно было для другого рецепта, создайте его заново.
- Safe OS и Setup Dynamic Update, которые в этот раз не искали или не нашли, больше не удаляются из `Config\Updates\Catalog` вместе с прошлым накопительным.
- Куст реестра, который держит антивирус, сборка ждёт около полутора минут, а не 10 секунд, прежде чем остановиться.
- Если рабочую папку не удалось удалить после сборки (файл занят), об этом выводится предупреждение. Файл-метка удаляется последним, поэтому следующий запуск узнает свою папку и очистит её.
- ISO, который подключил запуск, убитый до уборки, следующий запуск отключает, а не принимает за открытый вами в Проводнике. Пароли Wi-Fi, выгруженные таким запуском во временную папку, удаляются при следующем запуске.
- Рецепт без пути к ISO даёт понятную ошибку с подсказкой про `-IsoPath`, а не ошибку привязки параметра.
- Если загрузчик, запущенный с ярлыка, падает (например, нет сети), окно ждёт Enter, а не закрывается сразу.
- **Первый вход не зависает на одной программе.** Установка одной программы через winget прерывается через 30 минут, а программа ставится снова при следующем входе. Код winget «установлено, нужна перезагрузка» считается успехом, а вывод winget теперь попадает в лог первого входа.
- Сеть Wi-Fi, которая не добавилась при первом входе (например, драйвер Wi-Fi ещё не стоит), больше не теряется: она ждёт следующего входа и удаляется, когда первичная настройка закончена.
- **`-Restore` не обрывается из-за одной плохой записи.** Файл отката от более новой версии не читается с понятной ошибкой, записи без нужных полей пропускаются с предупреждением, а неизвестная этой версии программа остаётся в файле, не мешая вернуть остальное.
- Ключ реестра профиля Default, удалённый `-Online`, при `-Restore` больше не создаётся у текущего пользователя, если у него этого ключа не было.
- `-Online` и `-Restore` предупреждают, если скрипт запущен от другой учётной записи, чем вошедшая в Windows (в окне UAC ввели логин и пароль администратора): настройки текущего пользователя тогда достанутся администратору.

## 1.11.0

- **Удаление Microsoft Edge категорией профиля.** Новая категория `edge` («Microsoft Edge») удаляет Edge скриптом [EdgeRemover](https://github.com/he3als/EdgeRemover) от he3als, который лежит без изменений в `ThirdParty\EdgeRemover`. DISM не может убрать Edge из образа, поэтому в собранной Windows его удаляет первый вход, после программ из `Apps.txt`, а `-Online` удаляет его сразу. `-Restore` ставит Edge обратно, для этого нужен интернет. WebView2 остаётся. Категория по умолчанию выключена: включайте её по номеру в списке категорий или `"Enabled": true` в профиле, только если в `Apps.txt` есть другой браузер.
- В категориях профиля появилось поле `Uninstall`: программы, которые удаляются своим скриптом, а не средствами DISM. Пока это только `MicrosoftEdge`.
- Очистку хранилища компонентов (`/ResetBase`) теперь можно включить в сводке и для скачанных обновлений: раньше этот пункт появлялся, только если в папке были свои обновления.

## 1.10.1

- Накопительное обновление 24H2 и 25H2 вместе с контрольным KB5043080 больше не падает с «An error occurred applying the Unattend.xml file from the .msu package». Microsoft требует ставить их одним вызовом DISM из папки, где лежат только они, поэтому все накопительные обновления Windows из `Config\Updates` теперь ставятся так: в отдельную папку, установка самого нового через `dism.exe /Add-Package`. Обновление .NET, языковые пакеты и `.cab` ставятся по-прежнему по одному.

## 1.10.0

Четыре новые возможности.

- **Свежие обновления сами.** `-DownloadUpdates` (в сводке «Скачать свежие обновления из каталога Microsoft») находит в каталоге Центра обновления последнее накопительное обновление и обновление .NET для выпуска и архитектуры выбранной редакции, а с обновлением установщика ещё Safe OS и Setup Dynamic Update. Скачанное проверяется по контрольной сумме и хранится в `Config\Updates\Catalog`, старое удаляется.
- **Пересборка каждый месяц.** `-Recipe <рецепт> -Schedule Monthly` создаёт задание планировщика, которое 15-го числа пересобирает ISO по рецепту со свежими обновлениями. `-Schedule Off` удаляет его. В пошаговом режиме это предлагается после сборки со скачанными обновлениями.
- **Рецепт и отчёт.** После сборки рядом с ISO появляются `<имя ISO>.lunq.json` (всё, из чего собран ISO, с контрольными суммами) и `<имя ISO>.lunq.html` (отчёт «до и после» по категориям профиля). `-Recipe` повторяет сборку по рецепту, заданные параметры важнее него.
- **Профиль для этой Windows и откат.** `-Online` (в начале пошагового режима «Применить профиль к этому компьютеру») применяет профиль к работающей Windows без ISO. Перед каждым изменением запоминается, как было; тот же файл отката кладётся и в собранный образ. `-Restore` возвращает убранное по категориям, `-Category` ограничивает категории для `-Online` и `-Restore`, а также для сборки.
- **Копия этого компьютера.** `-HostDrivers` встраивает драйверы этого компьютера и без пошагового режима, `-HostApps` добавляет к `Apps.txt` его программы из `winget export`, `-HostWifi` переносит сети Wi-Fi (пароли лежат в ISO открытым текстом до первого входа, поэтому пункт по умолчанию выключен).
- В сводке появились пункты скачивания обновлений, программ и сетей Wi-Fi этого компьютера, поэтому номера пунктов ниже обновлений сдвинулись.

- Драйверы этого компьютера, выгруженные для сборки, удаляются из `%TEMP%` в конце запуска. С драйвером видеокарты это 1–3 ГБ на системном диске.

## 1.2.0

- Тесты Pester и проверка PSScriptAnalyzer в GitHub Actions на каждый PR (Windows PowerShell 5.1 и PowerShell 7).
- Очистка хранилища компонентов идёт через `dism.exe`: в модуле DISM старых Windows 10 у `Repair-WindowsImage` нет нужных параметров, и сборка обрывалась в конце. Неудачная очистка больше не срывает сборку.
- Предупреждение, если Windows на компьютере старше образа: DISM такой системы может не справиться с обновлениями.
- Записи реестра пишутся через .NET, а не через `reg.exe`: значения с кавычками и `\` в конце больше не искажаются. Ошибки в записях профиля (тип, число, действие) видны сразу при чтении профиля.
- Файл ответов задаёт все поля первой страницы установщика, и она больше не показывается.
- Остатки прерванного запуска в своей рабочей папке больше не дают предупреждения.
- ISO, уже открытый в Проводнике, не отключается скриптом.
- Рабочая папка может содержать пробел.
- oscdimg ищется и в папке ADK для ARM64.
- Скрипт после установки с ненулевым кодом выхода считается неудачным.
- Категория `drivers` выключена по умолчанию; из профиля убраны записи для Cortana и WordPad, которых нет в 26H2.
- Модуль разложен по файлам в `Modules\LunqDebloater\Private`, появился манифест с версией.
- Справка `Get-Help` описывает все параметры. Добавлены лицензия MIT и этот файл.
