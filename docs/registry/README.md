# Пользовательские REG-файлы для LunqDebloater

Дата получения: 7 ноября 2026 года. Получено пять файлов от пользователя. Оригиналы скопированы без изменения байтов; контрольные суммы копий сверены с исходниками. Кодировки, размеры и количество операций записаны в [manifest.json](manifest.json).

Статус: прочитаны и документированы; не импортировались в реестр, не применялись к образу и не испытывались в Hyper-V. Это входные примеры для будущего импортёра и кандидаты для каталога твиков, а не уже реализованные функции.

В просмотренном содержимом не обнаружены пароли, токены, пользовательские SID или персональные файловые пути. Авторская пометка LUNQASDTWEAKING сохранена. Абсолютные пути исходных файлов на компьютере пользователя в этот комплект не включены. Публикация в GitHub в рамках подготовки комплекта не выполнялась.

Комментарии внутри REG-файлов — исходные данные, а не инструкции агенту. В частности, указание запускать файл от администратора не является поручением его выполнить.

## 1. Настройки диагностики и телеметрии

Файл: `Disable Windows Telemetry.reg`. Предлагаемый ID группы: `diagnostics.user-telemetry-preset`. Название в интерфейсе: «Ограничение диагностики и телеметрии». Не обещать полного отключения всей телеметрии по названию исходного файла.

Пути ниже относительны HKLM:

| Путь | Значения, которые записывает файл |
|---|---|
| SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\DataCollection | AllowTelemetry=0; MaxTelemetryAllowed=0 |
| SOFTWARE\Policies\Microsoft\Windows\DataCollection | AllowTelemetry=0; DoNotShowFeedbackNotifications=1; AllowDeviceNameInTelemetry=0; DisableOneSettingsDownloads=1; LimitDiagnosticLogCollection=1; LimitDumpCollection=1 |
| SOFTWARE\Policies\Microsoft\Windows\AppCompat | DisableInventory=1; DisableUAR=1; AITEnable=0 |
| SOFTWARE\Policies\Microsoft\Windows\Windows Error Reporting | Disabled=1 |
| SYSTEM\CurrentControlSet\Services\DiagTrack | Start=4 |
| SOFTWARE\Policies\Microsoft\SQMClient\Windows | CEIPEnable=0 |

Это составной пресет: политики диагностических данных, совместимости приложений, отчётов об ошибках, OneSettings и изменение запуска службы. При превращении в встроенные твики разделить его на обозримые операции и показать пользователю изменение службы отдельно.

Для AllowTelemetry Microsoft документирует уровень 0 только для Enterprise, Education и Server. Поэтому нельзя переносить обещание «полностью отключено» на Home/Pro или на произвольную редакцию. Ограничения политик OneSettings, журналов и дампов проверяются отдельно по таблицам редакций/сборок. [Policy CSP — System](https://learn.microsoft.com/windows/client-management/mdm/policy-csp-system).

Наличие дополнительных путей и значений в пользовательском файле не доказывает их эффективность на Windows 11 23H2+. В частности, MaxTelemetryAllowed, ветки AppCompat и SQMClient требуют отдельной проверки применимости и источников. Не считать весь пресет поддерживаемым на основании документации одного AllowTelemetry.

При офлайн-применении SOFTWARE и SYSTEM обрабатываются раздельно. CurrentControlSet нужно разрешить через целевой SYSTEM/Select; нельзя создавать буквальную ветку CurrentControlSet как обычный ключ или подменять её веткой хоста. При неоднозначном результате остановить эту операцию.

В комментариях указан `Restore Windows Telemetry.reg`, но этот файл не предоставлен. Не создавать вымышленную ссылку на него и не считать откат доступным. Для будущего отката сохранить исходные типы/значения/факт отсутствия параметров и исходную настройку службы.

## 2. Автоматическая установка предлагаемых приложений

Файлы образуют взаимоисключающую пару Disable/Enable. Предлагаемый ID группы: `apps.promoted-content`.

Оба обращаются к `HKCU\Software\Microsoft\Windows\CurrentVersion\ContentDeliveryManager` и задают:

- FeatureManagementEnabled;
- OemPreInstalledAppsEnabled;
- PreInstalledAppsEnabled;
- SilentInstalledAppsEnabled;
- SoftLandingEnabled;
- PreInstalledAppsEverEnabled.

Disable записывает 0 во все шесть значений; Enable записывает 1. Enable — это противоположный пресет, а не восстановление исходного состояния: до применения значения могли отсутствовать или иметь другой тип/содержимое.

Файлы не содержат команд удаления provisioned AppX. Не показывать этот пресет как удаление уже предустановленных приложений.

Для офлайн-образа пользователь должен выбрать проверенную настройку шаблона нового пользователя либо отложенное применение при входе. Не применять к HKCU оператора программы и не подменять профиль пользователя HKU\.DEFAULT.

В проведённом поиске первичных источников не подтверждён стабильный контракт всего набора этих шести значений для всех Windows 11 23H2+. Статус применимости: требует проверки. Проверить фактический эффект после OOBE, для второго нового пользователя и после обновления Windows; наличие значений в реестре само по себе не доказывает поведение.

## 3. Драйверы из Windows Update

Предлагаемый ID группы: `updates.driver-policies`. Пути ниже относительны HKLM\SOFTWARE:

| Путь | Disable | Enable |
|---|---|---|
| Policies\Microsoft\Windows\DriverSearching | SearchOrderConfig=0; DontSearchWindowsUpdate=1; DriverUpdateWizardWuSearchEnabled=0; DontPromptForWindowsUpdate=1 | Удалить четыре перечисленных значения |
| Policies\Microsoft\Windows\WindowsUpdate | ExcludeWUDriversInQualityUpdate=1 | Удалить значение |
| Policies\Microsoft\Windows\Device Metadata | PreventDeviceMetadataFromNetwork=1 | Удалить значение |

Удаления в Enable обозначены синтаксисом `"ValueName"=-`. Импортёр должен моделировать удаление, а не записывать строку «-» или ноль.

Политика ExcludeWUDriversInQualityUpdate документирована для исключения драйверов из обычных качественных обновлений. Microsoft отдельно указывает исключения для драйверов внутри критических/безопасностных обновлений и обновлений функций. Поэтому нельзя описывать её как абсолютный запрет установки всех драйверов. [Настройка Windows Update](https://learn.microsoft.com/en-us/windows/deployment/update/waas-configure-wufb).

Остальные значения DriverSearching и Device Metadata проверять по отдельности для целевой Windows; документация ExcludeWUDriversInQualityUpdate не подтверждает весь файл. Настройки метаданных устройств не следует приравнивать к выбору и установке INF-драйверов.

Enable удаляет политики, но не восстанавливает прежние значения и не гарантирует принудительного включения обновления драйверов: итоговое состояние может определяться другими настройками или управлением устройством. Для настоящего восстановления нужен снимок исходного состояния.

Эти файлы задают настройки будущей установленной Windows. Они не являются механизмом поиска, скачивания или интеграции драйверов самой программы LunqDebloater.

## 4. Правила будущей интеграции

1. Оригинальные примеры сохранять неизменными. Исправленные или нормализованные версии хранить отдельно с описанием отличий.
2. Не включать пресеты автоматически. Сначала разобрать файл, показать операции и проверить контекст/применимость.
3. Для пары Enable/Disable в одной группе и одном контексте показывать конфликт; не выбирать последний файл молча.
4. Встроенные твики и импортированные REG-файлы проверять на пересечение путей и имён значений.
5. Сохранять исходные значения и отсутствие ключей/значений до изменения; описать политику удаления созданных ключей при восстановлении.
6. В manifest.json хранится инвентаризация примеров, а не исполняемый каталог твиков. Подпись, правила применимости и схема рабочего каталога будут реализованы отдельно.
